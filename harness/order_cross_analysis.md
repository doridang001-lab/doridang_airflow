# 주문 교차분석 운영

- DAG: `DB_OrderCrossAnalysis_Dags`. 정기 실행은 KST 08~23시 매시 10분·40분이다.
- 기존 `order_cross_YYMMDD.parquet`의 18개 컬럼명·순서·자료형과 원본 상품번호 의미를 유지한다.
- 분류/집계는 `DB_OrderCrossAnalysis_core.py`, 입출력/검증/재처리는 `DB_OrderCrossAnalysis.py`에 둔다.

## 집계 의미

- 같은 주문에서 각 메인과 함께 선택한 품목을 집계한다. 주문 식별자는 판매일·수집원·브랜드·매장·주문번호이다.
- 같은 메인 반복으로 상대 수량·금액을 곱하지 않는다. 서로 다른 메인에 연결된 금액은 중첩될 수 있어 전체 매출 합계가 아니다.
- `pair_type`은 기존 분류에 `리뷰`, `리뷰참여`, `미선택`, `미분류`를 추가한다. 컬럼은 추가하지 않는다.
- 검수 완료 매핑, 마스터 수동분류, 마스터 분류 순서로 적용하며 리뷰·거절의 명시적 마커를 별도 처리한다.
- 표준 메뉴명은 검수된 이름만 사용한다. 확정되지 않은 메뉴를 유사 문자열만으로 통합하지 않는다.
- 기준 메뉴는 주문서의 `menu_name`과 실제 품목명의 일치로 판단하고 실제 상품번호를 유지한다. 상품 마스터의 메인 분류가 없어도 주문을 분석한다. 분류상 메인인 추가 메뉴도 같은 주문의 기준 메뉴로 포함한다.
- 주문서 메뉴명에 대응하는 품목 행이 없으면 `MENU::` 가상번호와 `main_source=menu_name`을 사용한다. 이때 기존의 검수된 표준명이 있으면 활용한다. 리뷰·미참여·수수료 이름은 기준 메뉴로 삼지 않는다.
- `item_mapping.is_main`은 상품 분류이며 주문별 기준 메뉴 역할과 다르다. `unresolved_main_orders`는 유효한 주문서 메뉴명과 분류상 메인이 모두 없는 주문만 센다.

## 보조 자료와 검증

- `_support/<YYMMDD>/<생성번호>/` 아래 `main_orders.parquet`, `standard_pairs.parquet`, `item_mapping.parquet`, `quality.json`을 저장한다.
- 기존 parquet 메타데이터의 생성번호가 가리키는 보조 자료만 읽는다. 컬럼을 추가해서 연결하지 않는다.
- 보조 자료·원본·매핑·기존 parquet 내용의 해시를 확인한다. 읽기 실패, 스키마 오류, 매핑 충돌을 정상 빈 파일로 덮지 않는다.
- 선택률은 표준 메뉴별 고유 동시 주문 수 / 메인 전체 주문 수이다. 추가 선택이 없는 주문도 분모에 포함한다.
- 표준 메뉴의 주문 수는 원본 주문 단위에서 계산한다. 상품번호별 집계 결과나 일별 선택률을 단순 평균/합산하지 않는다.
- 모든 날짜·매장의 입력 행수, 제외 사유, 분석 주문 수, 메인 미확정 주문 수를 품질 기록으로 확인한다.
- 품질 검증 통과는 모든 원본 메뉴의 품목 분류 완료를 뜻하지 않는다. 미분류 품목도 교차 집계하며 주문서 근거가 없어 제외된 주문은 별도로 보고한다.

## 실행과 승인

- 코드 배포만으로 OneDrive를 수정하지 않는다. Airflow 변수 `order_cross_publish_enabled`의 기본값은 `false`이며 승인 전 DAG는 명시적으로 건너뛴다.
- 실제 OneDrive 반영 승인 후 단일 실행은 `{"sale_date":"2026-09-08","publish":true}`, 전체 실행은 `{"backfill":true,"publish":true}`를 사용한다.
- 지속 운영 승인 후에만 `order_cross_publish_enabled=true`로 설정한다. 변수 설정 자체도 운영 승인 범위에 포함한다.
- 직접 파이프라인 호출은 `allow_publish=True`를 명시해야 운영 경로에 쓸 수 있다. 로컬 검증은 `output_root`를 사용한다.
- 정기 실행은 최근 3일의 변경을 먼저 처리하고 과거 변경은 최대 10일씩 처리한다. 보조 자료까지 유효한 날짜만 완료로 판정한다.
- 전체 재처리는 전일까지 존재하는 정규 일별 파일을 대상으로 한다. 재실행은 변경/실패 날짜부터 이어간다. 처리 실패 날짜가 있으면 전체 완료로 보고하지 않는다.
- 실패 시 기존 파일을 보존한다. 임시 복구본은 `LOCAL_DB/temp/backups/order_cross/<실행ID>/`에 격리하고 성공 또는 정상 롤백 후 삭제한다.

## 로컬 검증

```powershell
python -X utf8 -m pytest tests/test_order_cross_analysis.py -q -o cache_dir=.tmp/pytest_order_cross
python -X utf8 scripts/validate_order_cross.py --output-root .tmp/order_cross_final
```

- `--date YYYY-MM-DD`는 반복 지정할 수 있다. 기본값은 완료된 전체 기간이며, `--force`는 유효한 체크포인트도 다시 계산한다.
- 검증 스크립트는 OneDrive에 쓰지 않는다. 입력 사본, 후보 결과, 비교 결과는 지정한 로컬 경로 아래에 저장한다.
- `summary.json`의 전체 대상 날짜와 완료 날짜 일치, 실패 0건, 모든 날짜의 `independent_reference` 검증을 확인한다.
- 기존 보고서는 같은 생성번호의 보조 자료를 읽어 분모를 계산한다. 자료 미준비/입력 변경이면 `교차분석 갱신 대기`로 표시하고 자동 재발송하지 않는다.
