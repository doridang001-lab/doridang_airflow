### 1. 최신 "주" 선택을 행 단위 → 주 단위로 변경 (275-281행)

`DB_Hall_Sales_Target.py`는 `(기준월, week_start)` 2키로 집계하므로 월경계 주는 **같은 `입력날짜`로 2행**이 생긴다. `iloc[-1]`은 그중 1행만 집는 것이 버그의 근원.

현재:
```python
    # ── 최신 주 결정 ──────────────────────────────────────────
    latest    = sale_df.sort_values("입력날짜").iloc[-1]
    ym        = latest["기준월"]          # "2026-05"
    wk_label  = latest["기준주"]          # "5월5주차"
    entry_dt  = latest["입력날짜"]        # 입력날짜(Timestamp)
    week_start = (entry_dt - timedelta(days=7)).date()
    week_end   = (entry_dt - timedelta(days=1)).date()
```

변경:
```python
    # ── 최신 주 결정 ──────────────────────────────────────────
    # 월경계를 걸친 주는 (기준월, week_start) 2키 집계 때문에 같은 입력날짜로 2행이 된다.
    # 주간보고는 7일 전체 기준이므로 해당 입력날짜의 모든 행을 한 주로 묶는다.
    sale_df    = sale_df.sort_values(["입력날짜", "기준월"])
    entry_dt   = sale_df["입력날짜"].max()          # 입력날짜(Timestamp)
    week_rows  = sale_df[sale_df["입력날짜"] == entry_dt]
    latest     = week_rows.iloc[-1]                 # 라벨/월누계 기준 = 주의 마지막 날이 속한 달
    ym         = latest["기준월"]                   # "2026-08"
    wk_label   = latest["기준주"]                   # "8월1주차"
    week_start = (entry_dt - timedelta(days=7)).date()
    week_end   = (entry_dt - timedelta(days=1)).date()
```

`week_start` / `week_end`는 이미 7일 전체를 가리키므로 계산식 그대로 둔다.
`ym`은 월누계·월목표·마케팅 월 필터 기준이므로 지금처럼 "주의 마지막 날이 속한 달"을 유지한다.

### 3. 객단가는 합산 금지 — 재계산 (365-382행)

`테이블_객단가`, `점심_테이블_객단가`, `저녁_테이블_객단가`는 평균값이라 `sum()`하면 틀린다. 이미 월누계용으로 있는 `_ms_aov()`를 일반화해 주간에도 재사용한다.

현재:
```python
    def _ms_aov(prefix_매출, prefix_cnt):
        """월 누계 테이블단가 = 누계매출/누계영수건수"""
        total = ms(prefix_매출)
        cnt   = ms(prefix_cnt)
        return int(total / cnt) if cnt else 0
```

변경:
```python
    def _aov(rows, col_매출, col_cnt):
        """테이블단가 = 매출합/영수건수합 (평균값이라 행 단순합산 불가)"""
        total = int(rows[col_매출].sum())
        cnt   = int(rows[col_cnt].sum())
        return int(total / cnt) if cnt else 0

    def _ms_aov(col_매출, col_cnt):
        return _aov(mrows, col_매출, col_cnt)

    def _ws_aov(col_매출, col_cnt):
        return _aov(week_rows, col_매출, col_cnt)
```

`sale_rows` 리스트(371-382행)에서 "이번주" 객단가 3개를 교체:

| 행 | 현재 (w_act) | 변경 후 |
|---|---|---|
| `("테이블단가", ...)` | `ws("테이블_객단가")` | `_ws_aov("매출", "영수건수")` |
| `("점심 테이블단가", ...)` | `ws("점심_테이블_객단가")` | `_ws_aov("점심_매출", "점심_영수건수")` |
| `("저녁 테이블단가", ...)` | `ws("저녁_테이블_객단가")` | `_ws_aov("저녁_매출", "저녁_영수건수")` |

월누계 쪽(`_ms_aov("매출","영수건수")` 등)과 객단가 **목표**(`mt.get("aov")` 등, `monthly_targets`에서 옴)는 그대로 둔다.

### 4. 마케팅 주목표도 7일 기준으로 (310행)

마케팅 **실적**(`mkt_week`, 303-306행)은 이미 `week_start ~ week_end` 7일 전체를 합산하는데, **목표**(`_mkt_weekly_targets`)는 `ym`에 속한 날만 센다. 월경계 주에서 실적 7일 vs 목표 2일이 되어 달성률이 부풀려진다(실측: 플레이스 유입 목표 1,600 / 실적 2,420 = 151%).

현재:
```python
    mwt = _mkt_weekly_targets(ym, week_start, marketing_monthly_targets)
```

변경 — 주에 걸친 모든 달의 target을 합산:
```python
    mwt = _mkt_weekly_targets_span(week_start, marketing_monthly_targets)
```

`_mkt_weekly_targets()`(176-183행) 옆에 추가:
```python
def _mkt_weekly_targets_span(week_start, mkt_monthly):
    """주가 걸친 모든 달의 일할 target을 합산 (월경계 주 대응)."""
    yms = {(week_start + timedelta(days=i)).strftime("%Y-%m") for i in range(7)}
    out: dict[str, int] = {}
    for ym in yms:
        for k, v in _mkt_weekly_targets(ym, week_start, mkt_monthly).items():
            out[k] = out.get(k, 0) + v
    return out
```

기존 `_mkt_weekly_targets()`는 그대로 남겨 재사용한다(단월 주에서는 결과 동일).

### modules/transform/pipelines/db/DB_Hall_Sales_Excel.py (176-183행)

```python
def _mkt_weekly_targets(ym, week_start, mkt_monthly):
    cnt = sum(
        1 for i in range(7)
        if (week_start + timedelta(days=i)).strftime("%Y-%m") == ym
    )
    t   = mkt_monthly.get(ym, {})
    dim = calendar.monthrange(int(ym[:4]), int(ym[5:]))[1]
    return {k: round(v / dim * cnt) for k, v in t.items()}
```
