# 쿠팡이츠수집확장보완계획

## Task

쿠팡이츠 수집 크롬확장의 배치 성공률이 3일간 급락했다(성공 20 → 3 → **0**).
원인은 쿠팡 측 차단이 아니라 **확장 자체의 10057 오탐**과 **페이지 언마운트 복구 부재**다.
1단계로 오탐을 제거하고, 2단계로 복구·백오프 로직을 넣어 버려지던 매장을 되살린다.

### 진단 근거 (3일치 이슈 로그 전수 확인 — 재조사 불필요)

`⛔ 쿠팡 제한(10057) 감지` **38건 중 진짜 주문 API rate limit은 사실상 0건**이다.

| keyword | 건수 | 실제 정체 |
|---|---|---|
| `ACCESS_DENIED` | 22 | 스니펫이 전부 `쿠폰 관리 바로가기 ACCESS_DENIED` / `광고 설정하기 ACCESS_DENIED` → **쿠폰·광고 위젯 부분실패** |
| `10057:` | 11 | 스니펫이 `쿠폰 관리 바로가기 10057: 과도한 요청...` → **이것도 쿠폰 위젯**. 여러 날/여러 매장에서 `매출액: 33,600원 (1건)` 동일 스니펫 반복 = 캐시된 위젯 에러 |
| `(10057)` | 5 | **확장이 자기 진행 모달에 찍은 로그를 자기가 다시 읽음** (자가매칭) |

결정적으로 위 스니펫 대부분에 `매출액: 429,900원 (14건)`, `4,814,800원 (161건)` 같은
**주문 요약이 정상 렌더된 상태**가 함께 잡혀 있다 → **수집 가능했던 매장을 버리고 있었다.**

자가매칭 실증 로그(2026-08-02 02:01:09):
```
keyword=(10057) | ...집 🚫 닭도리탕 전문 도리당 창원내서점 ⛔ 쿠팡 제한(10057) — 현재 매장 패스 [오전 1:59:47] → 매장...
```
이건 페이지 텍스트가 아니라 확장 모달 DOM이다:
`🏪 …다중매장 수집`(제목) + `__ms_icon_N`(🚫) + 매장명 + `__ms_status_N` + `__ms_debug_N` 첫 줄.

## Do Not Ask — Decide Yourself

- 파일이 이미 존재하면: 덮어쓰기 (단, `.bak_20260803` 백업 먼저)
- 헬퍼 함수 배치 위치가 모호하면: 관련 함수 바로 위/아래, 같은 객체 리터럴 안
- 타입 힌트/JSDoc: 기존 파일과 동일하게 (거의 없음 — 붙이지 않는다)
- 주석: 최소화. WHY만 남기고 WHAT 설명 금지. 한글로 작성 (기존 파일 관례)
- 변수명·함수명: camelCase, private는 `_` 접두 (기존 파일과 동일)
- 로그 문구 어투: 기존 이모지 + 한글 스타일 유지 (`⛔`, `⏳`, `⚠️`, `✅`, `📋`)
