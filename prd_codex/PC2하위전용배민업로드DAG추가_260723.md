# PC2(하위) 전용 배민 업로드 DAG 추가

## Task
배민 매크로는 2대 PC가 같은 `DB_Beamin_Macro_Dags`를 돌리고, `.env`의 `BAEMIN_MACRO_ROLE=top/bottom`으로 상/하위 절반씩 나눠 수집한 뒤 OneDrive 공유 인박스 `_baemin_upload_inbox/manual__top__<run_id>` / `manual__bottom__<run_id>` 폴더로 내보낸다. analytics 적재·검증은 중앙 PC의 `DB_Beamin_Macro_Upload_Dags`(KST 07:40) 하나가 담당하는데, `ingest_inbox()`가 인박스의 **모든** `manual__*` 폴더를 먹고 삭제하므로 2번 PC가 07:40까지 못 끝내면 하위 매장 데이터가 다음날 07:40까지 24시간 밀린다.
중앙 PC에 오전 08:00~12:30 사이 주기적으로 돌면서 **`manual__bottom__*` 폴더만** 적재·검증·알림하는 두 번째 Upload DAG을 추가한다. 처리할 폴더가 없으면 downstream 전체를 skip해 텔레그램 스팸을 막는다.

## Implementation Steps

### 1. `DB_Beamin_pc2_distribute.py` — 폴더 패턴 인자화
현재 `ingest_inbox()`(36행)가 `inbox_dir.glob("manual__*")`을 하드코딩(46행)하고 있다. 모듈 상수 + 기본 인자로 뺀다.

```python
DEFAULT_FOLDER_PATTERN = "manual__*"


def ingest_baemin_upload_inbox(folder_pattern: str = DEFAULT_FOLDER_PATTERN, **context) -> dict[str, Any]:
    """Upload inbox의 manual__* 폴더를 적재하고 폴더 meta를 함께 반환한다."""
    return ingest_inbox(UPLOAD_INBOX_DIR, read_meta=True, folder_pattern=folder_pattern)


def ingest_inbox(
    inbox_dir: Path,
    read_meta: bool = False,
    folder_pattern: str = DEFAULT_FOLDER_PATTERN,
) -> dict[str, Any]:
    label = inbox_dir.name
    ...
    folders = sorted(p for p in inbox_dir.glob(folder_pattern) if p.is_dir())
    if not folders:

```

- `"처리 대상 없음"` / `"적재 완료"` 로그에 `folder_pattern`을 함께 남긴다(어느 DAG이 무엇을 훑었는지 추적).
- `_cleanup_processed_folder()`의 `startswith("manual__")` 가드는 **수정하지 않는다** — `manual__bottom__*`도 통과한다.
- `ingest_baemin_pc2_inbox()`(레거시 PC2 인박스)는 손대지 않는다.

### 2. `DB_Beamin_Macro_upload.py` — 패턴 통과 + skip 게이트 추가
`ingest()`(148행)를 아래처럼 바꾸고, 바로 아래에 게이트 함수를 신규 추가한다.

```python
def ingest(folder_pattern: str = "manual__*", **context) -> str:
    result = ingest_baemin_upload_inbox(folder_pattern=folder_pattern)
    meta = result.get("meta") or {}
    for key, value in meta.items():
        context["ti"].xcom_push(key=key, value=value)
    context["ti"].xcom_push(key="ingest_stats", value=result.get("stats") or {})
    return result.get("summary", "upload inbox 적재 완료")


def has_ingested_folders(**context) -> bool:
    """적재된 폴더가 없으면 downstream(검증·알림·retry)을 전부 skip한다."""
    stats = context["ti"].xcom_pull(task_ids="ingest", key="ingest_stats") or {}
    cleaned = int(stats.get("cleaned") or 0)
    if not cleaned:
        logger.info("upload 대상 폴더 없음 → downstream skip (stats=%s)", stats)
    return bool(cleaned)
```

- 기준은 `folders`가 아니라 `cleaned`(성공 적재 후 정리된 폴더 수). `folders>0`인데 전부 skip/failed면 검증할 meta가 없으므로 skip이 맞다.
- `precheck_manual`, `validate_orders`, `validate_ad_funnel`, `validate_toorder`, `notify_upload_result`, `trigger_retry_if_needed`는 **수정하지 않는다**. 전부 `task_ids="ingest"` / `"validate_toorder"` 등 task_id 문자열로 XCom을 당기므로, 새 DAG에서 task_id를 기존과 동일하게 유지하면 그대로 동작한다.

### 3. `modules/transform/utility/schedule.py` — 스케줄 상수
`SMD_BAEMIN_UPLOAD_TIME = "40 7 * * *"`(74행) 바로 아래에 추가한다.

```python
SMD_BAEMIN_UPLOAD_PC2_TIME = "0,30 8-12 * * *"  # KST 08:00~12:30 30분 간격 (하위 PC 도착분 sweep)
```

> Airflow 2.10.4에는 `MultipleCronTriggerTimetable`이 없어 "8:30, 9:00, 10:00, 11:00, 12:00" 목록을 단일 cron으로 표현할 수 없다. 요청 시간대를 포함하는 30분 간격 cron으로 대체한다. 빈 run은 ShortCircuit 게이트에서 즉시 skip되므로 비용은 사실상 없다.

### 4. `dags/db/DB_Beamin_Macro_Upload_Pc2_Dags.py` — 신규 DAG
`DB_Beamin_Macro_Upload_Dags.py`를 그대로 복제하되 아래 3가지만 다르다.
1. `schedule=SMD_BAEMIN_UPLOAD_PC2_TIME`, `tags=["db", "baemin", "upload", "pc2"]`
2. `ingest`에 `op_kwargs={"folder_pattern": "manual__bottom__*"}`
3. `ingest` 뒤에 `ShortCircuitOperator` 게이트 `has_pending` 삽입

```python
"""하위(bottom) PC 도착분 전용 배민 업로드 DAG.

중앙 PC에서만 unpause한다. 07:40 `DB_Beamin_Macro_Upload_Dags`가 이미 먹은
날은 인박스가 비어 있어 게이트에서 downstream 전체가 skip된다.
"""

from __future__ import annotations

from datetime import timedelta
from pathlib import Path

import pendulum
from airflow import DAG
from airflow.operators.python import PythonOperator, ShortCircuitOperator
from airflow.utils.trigger_rule import TriggerRule

from modules.transform.pipelines.db.DB_Beamin_Macro_upload import (
    has_ingested_folders,
    ingest,
    notify_upload_result,
    precheck_manual,
    trigger_retry_if_needed,
    validate_ad_funnel,
    validate_orders,
    validate_toorder,
)
from modules.transform.utility.notifier import on_failure_callback_no_telegram
from modules.transform.utility.schedule import SMD_BAEMIN_UPLOAD_PC2_TIME

dag_id = Path(__file__).stem
BOTTOM_FOLDER_PATTERN = "manual__bottom__*"

default_args = {
    "retries": 1,
    "retry_delay": timedelta(minutes=5),
    "depends_on_past": False,
    "email_on_failure": False,
    "email_on_retry": False,
    "on_failure_callback": on_failure_callback_no_telegram,
}


with DAG(
    dag_id=dag_id,
    schedule=SMD_BAEMIN_UPLOAD_PC2_TIME,
    start_date=pendulum.datetime(2024, 1, 1, tz="Asia/Seoul"),
    catchup=False,
    max_active_runs=1,
    max_active_tasks=1,
    default_args=default_args,
    tags=["db", "baemin", "upload", "pc2"],
) as dag:
    t_ingest = PythonOperator(
        task_id="ingest",
        python_callable=ingest,
        op_kwargs={"folder_pattern": BOTTOM_FOLDER_PATTERN},
        execution_timeout=timedelta(minutes=60),
    )

    t_gate = ShortCircuitOperator(
        task_id="has_pending",
        python_callable=has_ingested_folders,
    )

    t_precheck = PythonOperator(
        task_id="precheck_manual_baemin_orders",
        python_callable=precheck_manual,
        trigger_rule=TriggerRule.ALL_DONE,
        execution_timeout=timedelta(minutes=15),
    )

    t_validate_orders = PythonOperator(
        task_id="validate_orders",
        python_callable=validate_orders,
        trigger_rule=TriggerRule.ALL_DONE,
    )

    t_validate_ad_funnel = PythonOperator(
        task_id="validate_ad_funnel",
        python_callable=validate_ad_funnel,
        pool="selenium_pool",
        trigger_rule=TriggerRule.ALL_DONE,
        execution_timeout=timedelta(minutes=120),
    )

    t_validate_toorder = PythonOperator(
        task_id="validate_toorder",
        python_callable=validate_toorder,
        trigger_rule=TriggerRule.ALL_DONE,
        execution_timeout=timedelta(minutes=30),
    )

    t_notify = PythonOperator(
        task_id="notify_upload_result",
        python_callable=notify_upload_result,
        trigger_rule=TriggerRule.ALL_DONE,
    )

    t_trigger_retry = PythonOperator(
        task_id="trigger_retry_if_needed",
        python_callable=trigger_retry_if_needed,
        trigger_rule=TriggerRule.ALL_DONE,
    )

    t_ingest >> t_gate >> t_precheck >> [t_validate_orders, t_validate_ad_funnel, t_validate_toorder] >> t_trigger_retry >> t_notify
```

핵심 주의점:
- downstream이 전부 `TriggerRule.ALL_DONE`이지만 `ShortCircuitOperator`는 기본 `ignore_downstream_trigger_rules=True`라 게이트가 False면 **전부 skipped**가 된다. 이 기본값을 끄면 안 된다.
- task_id는 기존 Upload DAG과 **글자 그대로 동일**하게 유지해야 한다(XCom pull 호환). 새로 추가된 `has_pending`만 예외.
- Retry DAG run_id는 `retry__<date>__attempt_1__<source_run_id>`이고 source_run_id가 DAG마다 달라 07:40 DAG과 충돌하지 않는다.

## Verification Loop
구현 완료 후 아래 루프를 **모든 Test Cases PASS까지** 반복한다.

```
LOOP until all PASS:
  1. Test Cases 순서대로 실행
  2. FAIL 항목 → 원인 분석
  3. 코드 수정
  4. 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

## Constraints
- `folder_pattern` 기본값은 반드시 `"manual__*"` — 기존 `DB_Beamin_Macro_Upload_Dags`와 레거시 `ingest_baemin_pc2_inbox()` 호출부가 인자 추가 없이 현행 동작을 유지해야 한다(하위호환 필수).
- 기존 07:40 `DB_Beamin_Macro_Upload_Dags.py`는 **수정하지 않는다**. 필터 없이 전부 처리하는 fast path로 남긴다(PC2가 일찍 끝난 날은 07:40에 통합 처리 → 새 DAG은 no-op skip).
- 새 DAG의 task_id는 기존 Upload DAG과 **글자 그대로 동일**해야 한다. `DB_Beamin_Macro_upload.py`의 검증/알림 함수들이 `task_ids="ingest"`, `task_ids="validate_toorder"`, `task_ids="validate_ad_funnel"`, `task_ids="precheck_manual_baemin_orders"`, `task_ids="trigger_retry_if_needed"` 문자열로 XCom을 당긴다. 이름을 바꾸면 조용히 빈 값이 흘러 검증이 무력화된다.
- `ShortCircuitOperator`의 `ignore_downstream_trigger_rules` 기본값(True)을 끄지 않는다. downstream이 전부 `TriggerRule.ALL_DONE`이라 이 값이 False면 skip이 안 먹는다.
- `_cleanup_processed_folder()`의 `startswith("manual__")` 가드와 `_merge_meta()`의 target_date 혼재 검사는 수정하지 않는다.
- `validate_ad_funnel`은 반드시 `pool="selenium_pool"` 유지 — 07:40 DAG과 셀레늄 경합을 막는다.
- 새 DAG은 중앙 PC에서만 unpause한다. 2번 PC에서는 pause 유지.
- 2번 PC `.env`의 `BAEMIN_MACRO_ROLE=bottom`이 전제다. 값이 빠지면 폴더가 `manual__<run_id>`로 생겨 새 DAG이 못 잡고 다음날 07:40 run이 뒤늦게 처리한다(데이터 유실은 아님).
