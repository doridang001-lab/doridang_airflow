## Task

### 3. 신규 `modules/transform/pipelines/sales/employee_accounts_export.py`

`accounts.js`의 `buildAccountsFromCsv()`와 **바이트 단위로 동일한 규칙**이어야 한다.

변환 규칙:
- 입력 CSV: `LOCAL_DB / '영업관리부_DB' / 'sales_employee.csv'`, `encoding='utf-8-sig'`
- **`dtype=str`로 읽어 계정ID 선행 0 보존** (`01037856589`이 `1037856589`가 되면 로그인 실패)
- 사용 컬럼: `담당자`, `매장명`, `플랫폼`, `계정ID`, `계정PW`
- 플랫폼 매핑: `{'배달의 민족':'baemin', '쿠팡이츠':'coupang', '요기요':'yogiyo', '땡겨요':'ddangyo'}`

- 담당자별 리스트를 `매장명` 기준 한글 정렬 (`locale` 불가 환경이므로 파이썬 기본 문자열 정렬 사용 — 한글 음절은 코드포인트 순 = 사전순)
- 출력 dict: `{담당자: [{"store":…, "platform":…, "id":…, "pw":…}, …]}`

출력 파일: `COLLECTOR_EXT_DIR / "accounts_data.js"`, `encoding='utf-8'`

### 9. `runner.js` — 백필 큐 덮어쓰기 수정

`finishBatch()`와 `finishRetry()` 두 곳이 `ce_backfill_queue`를 통째로 교체한다.
상위 50% 실행 후 하위 50%를 돌리면 **두 번째 실행이 첫 번째 실패 목록을 지우고**,
하위가 전부 성공하면 `chrome.storage.local.remove()`로 완전 삭제된다.

공통 헬퍼를 하나 만들어 두 곳에서 호출:

```js
// 같은 targetDate면 기존 큐와 합집합으로 병합한다.
// 이번 실행이 다루지 않은 매장(다른 half)은 성공 여부와 무관하게 보존한다.
async function saveBackfillQueue(incompleteStores, targetDate, runStores) {
  const prev = (await chrome.storage.local.get(['ce_backfill_queue'])).ce_backfill_queue;
  const runKeys = new Set((runStores || []).map(storeCompareKey));
  let merged = [];

  if (prev && prev.targetDate === targetDate && Array.isArray(prev.failedStores)) {
    // 이번 실행 대상이 아닌 기존 항목은 그대로 유지
    merged = prev.failedStores.filter(s => !runKeys.has(storeCompareKey(s)));
  }
  merged = uniq([...merged, ...incompleteStores]);

  if (merged.length > 0) {
    await chrome.storage.local.set({
      ce_backfill_queue: { enqueuedDate: getTodayStr(), targetDate, failedStores: merged }
    });
  } else {
    await chrome.storage.local.remove(['ce_backfill_queue']);
  }
  return merged.length;
}
```

`finishBatch()` 호출부:

```js
const allIncomplete = backfillStores();
const targetDate = hardThrottleBackfillDate || getRunDateStr(runDateMode);
const n = await saveBackfillQueue(allIncomplete, targetDate, runTargetStores);
if (n > 0) log(`📋 백필 큐 저장 — 미완료 매장 ${n}개`, 'info');
```

`finishRetry()`도 동일하게(메시지는 기존 `… (내일 배치 시 자동 재수집)` / `✅ 전체 성공 — 백필 큐 없음` 유지).

> `finishBatch`/`finishRetry`가 `async`가 아니면 `async`로 바꾸고 호출부에 `await`/`void` 처리.

### 10. `runner.js` — 백필 라운드 실패분 유실 수정

`runBatch()`는 백필 실행 **전에** 큐를 `remove`하고, 백필 종료 후 `storeStatusRows.clear()`로
상태를 비운다. 백필에서 또 실패한 매장이 이번 실행 half에 없으면 `backfillStores()`에 안 잡혀 **영구 유실**된다.

- 모듈 스코프에 `let carriedBackfillStores = [];` 선언
- 백필 라운드 종료 직후(`storeStatusRows.clear()` **직전**)에 `carriedBackfillStores = backfillStores();` 저장
- `runBatch` 시작 시 `carriedBackfillStores = [];`로 초기화
- Step 9의 `saveBackfillQueue` 호출 시 `uniq([...carriedBackfillStores, ...allIncomplete])`를 넘김
- 단, `carriedBackfillStores` 중 이번 실행 대상(`runTargetStores`)에 포함돼 재수집된 매장은 제외
  (`saveBackfillQueue`의 `runKeys` 필터가 처리하므로, carried는 incomplete와 합치기 전에
  `runKeys`에 없는 것만 남기면 됨)

> `enqueuedDate === getYesterdayStr()` 가드는 **변경하지 않는다**(범위 밖).

## Constraints

- **`dtype=str` 필수** — 계정ID 선행 0(`01037856589`, `0264088227`)이 사라지면 로그인 실패로 직결된다.
- 확장 수정은 **OneDrive `doridang_collector_개발용` 한 곳만**. `C:\airflow\coupang_extension_build`는 건드리지 않는다.
- `accounts.js`의 기존 file:// / SharePoint 폴백 분기를 **삭제하지 말 것**(다른 PC 안전망).
- `accounts.js` 하단의 동기 `window.ACCOUNTS = ACCOUNTS;` 유지(제거 시 로드 경합으로 큐가 빈다).
- `pickTargetStores`/`allStoreNamesSorted`/`storeCompareKey` **분할 로직은 정상이므로 수정 금지**.
- `enqueuedDate === getYesterdayStr()` 백필 소비 가드는 **변경 금지**(범위 밖).
- 확장 파일은 대용량(`runner.js` 88KB)이므로 전체 재작성 금지 — 해당 함수만 국소 수정.
- 기존 `.bak_*` 백업 파일들은 수정/삭제하지 않는다.
- `print` 금지 — Airflow 신규 코드는 `logger` 사용. (단 기존 DAG 파일 내 `print`는 그대로 둔다)
- `accounts_data.js`는 자동 생성물이므로 헤더에 `직접 수정 금지` 주석 필수.
- 계정 비밀번호가 평문으로 파일에 들어가므로, 생성물을 git에 커밋하지 말 것
  (확장 폴더는 OneDrive이며 git 대상 아님 — `C:\airflow` 쪽에 복사본을 만들지 말 것).
