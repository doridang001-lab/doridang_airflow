# 배민 주문서 전량 미수집 수정

## Task

`DB_Beamin_Macro_Dags`가 success(초록)로 끝나는데도 배민 주문내역이 **0건** 저장된다. target_date가 `logical_date - 1일`로 계산되면서 실제 실행일 기준 "그제"가 되고, 그 결과 `_set_date()`가 정상 동작하는 "어제" 라디오 경로 대신 **깨진 달력 경로(`_set_date_specific`)**로 빠져 전 매장이 `날짜 설정 실패, 건너뜀`으로 스킵된다. 실패가 태스크 상태에 반영되지 않아 8시간을 소진하고 초록으로 끝난다. target_date 오프바이원 + 달력 경로 + 조기중단을 고치고, 누락된 2026-07-26·07-27을 백필한다.

### 1. target_date 오프바이원 수정 (필수 — 이것만으로 매일 수집 복구)

`dags/db/DB_Beamin_Macro_Dags.py`의 `_target_date_from_context()`(:143)를 `data_interval_end` 기준으로 교체한다. 레포 기존 패턴(`dags/db/DB_ToOrderMenu_Dags.py:83-88`, `modules/transform/pipelines/db/DB_Daily_Corporate_Store_Report.py:159-160`)을 그대로 재사용.

```python
def _target_date_from_context(context) -> str:
    dag_run = context.get("dag_run")
    conf = (getattr(dag_run, "conf", None) or {}) if dag_run else {}
    if conf.get("target_date"):
        return conf["target_date"]
    data_interval_end = context.get("data_interval_end")
    if data_interval_end is not None:
        return pendulum.instance(data_interval_end).in_timezone(KST).subtract(days=1).format("YYYY-MM-DD")
    return pendulum.now(KST).subtract(days=1).format("YYYY-MM-DD")
```

- 정시 실행: `data_interval_end` = 실제 발화 시각(07-29 00:15 KST) → `2026-07-28` = 어제 ✅
- 수동 실행: `data_interval_end` = 트리거 시각 → 어제 ✅
- `conf.target_date` 백필 경로 유지 ✅

부수 정리: `_build_collection_notification`의 `validation_texts = [... for task_id in ()]`(:948-952)는 빈 튜플을 순회해 항상 빈 리스트다. 메일의 `[검증 요약]`이 늘 "없음"이고 `_has_validation_issue`도 죽어 있다. 단일 DAG 구성에는 검증 태스크가 없으므로(검증은 `DB_Beamin_Macro_Upload_Validate_Dags`가 수행) 죽은 코드를 `_VALIDATION_TASK_IDS`(:746)와 함께 제거한다.

def _set_date(driver, target_date: str) -> bool:
    """target_date에 맞는 날짜 필터 함수를 선택해 호출한다."""
    today = pendulum.now(KST).format("YYYY-MM-DD")
    yesterday = pendulum.yesterday(KST).format("YYYY-MM-DD")
    if target_date == today:
        return _set_date_today(driver) or _set_date_specific(driver, target_date)
    if target_date == yesterday:
        return _set_date_yesterday(driver)
    return _set_date_specific(driver, target_date)
```

LOOP until all PASS:
  1. Test Cases 순서대로 실행
  2. FAIL 항목 → 원인 분석
  3. 코드 수정
  4. 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

단, Test Case 6/8/9는 Selenium 실 수집이라 1회 실행에 수 분이 걸린다. 6이 FAIL이면 2번 DOM 덤프를 다시 떠서 셀렉터를 갱신한 뒤 재시도한다.

## Constraints

- **DOM 추측 금지** — `_set_date_specific` 셀렉터는 반드시 2번 덤프 결과에 근거해 작성한다. 현재 코드가 실패하는 이유가 정확히 "실제 DOM을 모른 채 셀렉터를 가정했기 때문"이다.
- `_set_date_yesterday` / `_set_date_today` 의 **동작하는 경로를 건드려 회귀시키지 말 것**. 공통 헬퍼 추출 시 클릭 JS 로직은 문자 그대로 보존한다.
- `collect_orders_for_driver` 반환 dict의 기존 키(`ok`, `validation`)는 유지한다. `reason`은 추가만 한다.
- 조기중단 `RuntimeError` 메시지에 `timeout`, `connection`, `disconnected` 등 `_CRASH_KEYWORDS`(`DB_Beamin_04_orders.py:54-59`) / `_is_session_issue` 매칭 문자열이 들어가면 안 된다. 세션 복구 로직으로 오인된다.
- 폴더 구조·파일명 변경 금지. 새 헬퍼는 기존 파일 안에 둔다.
- 스케줄 상수(`SMD_BAEMIN_COLLECT_BATCH1_TIME = "15 0 * * *"`)는 **변경하지 않는다**. 스케줄이 아니라 target_date 계산이 문제다.
- 디버그 스크립트는 일회성이므로 DAG에서 import 하지 않는다.

## Do Not Ask — Decide Yourself

- 파일이 이미 존재하면: 덮어쓰기
- import가 모호하면: Reference Code의 패턴 따라가기
- 타입 힌트 여부: 기존 파일과 동일하게
- 주석 여부: 최소화 (WHY만, WHAT 설명 금지)
- 변수명·함수명 스타일: snake_case, 기존 파일과 동일하게
- 조기중단 임계치: `_ORDERS_DATE_FILTER_ABORT_STREAK = 5`
- 디버그 스크립트 대상 매장: `도리당 강동점`
