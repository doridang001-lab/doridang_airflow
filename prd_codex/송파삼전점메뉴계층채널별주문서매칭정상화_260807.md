### 1. 채널간 메뉴 정규화 매칭 레이어 (원인 1·2 해결)

**1-1. `_canonical_menu_key(name) -> str` 신규 헬퍼** (`_strip_leading_tags` 근처, 537행 부근에 배치)

- 프로모션 대괄호 접두어를 반복 제거:

  `[우삼겹살]` `[얼큰 국물]` `[한그릇]` `[닭한마리]` `[국물양 조절 불가]` `[복날한정]` `[1인]`
- 단 `_SIZE_TAG_RE`(소/중/대/특/N인/N인분/반마리/한마리/뼈/순살)에 걸리는 태그는 **보존** (기존 `_strip_leading_tags` 규약 유지)
- 꼬리 수식 제거: `(밥포함)` `(공깃밥 포함)` `(공기밥 미포함)` `(2인이상)` `(1인 단품)` `1인분` `세트`
- 마지막에 `_normalize_item_key()` 적용 (공백/기호 제거 + 소문자화)
- 결과 예: `[한우 대창] 순살 곱도리탕` / `한우순살곱도리탕` → 둘 다 `한우대창순살곱도리탕`,
  `[재주문 1위] 도리당 닭도리탕` / `도리당 닭도리탕` → 둘 다 `도리당닭도리탕`

**1-2. `_ProductLookup.canonical_profile: dict[str, dict]` 신규** (`__init__` 584행 뒤에 추가)

4개 채널(okpos/posfeed/배민수동/쿠팡수동) 상품표를 **source 무관하게 전부 훑어** canonical key 하나로 합친다.

- `category` : 채널마다 값이 다르면 우선순위로 승자 결정
  `메인/1인/세트` > `사이드/음료/토핑/리뷰/옵션` > `기타`
  → 배민 `기타`가 posfeed `메인`에 의해 교정됨 (원인 2 해결)
- `대표메뉴` / `standard_menu_name` : 채널 무관 표준 메뉴명
- **`대표메뉴` 값 자체도 canonical 메인메뉴로 등록** — 쿠팡 옵션행 75건이 가리키는 대표메뉴 11종

def _ensure_boundary(df: pd.DataFrame, boundary: pd.Series) -> pd.Series:
    out = boundary.reindex(df.index).fillna(False).astype(bool).copy()
    if df.empty:
        return out
    for order_id, group in df.groupby("order_id", sort=False):
        if out.loc[group.index].any():
            continue
        role_name = group["item_name"].fillna("").astype(str)
        candidate = group.index[~role_name.str.contains(_FEE_LIKE_RE, na=False)]
        idx = candidate[0] if len(candidate) else group.index[0]
        out.at[idx] = True
    return out

## Verification Loop

구현 완료 후 아래 루프를 **모든 Test Cases PASS까지** 반복한다.

```
LOOP until all PASS:
  1. Test Cases 1~10을 순서대로 실행
  2. FAIL 항목 → 원인 분석 (A/B 표의 어느 케이스가 깨졌는지 특정)
  3. 코드 수정
  4. 전체 Test Cases 재실행

```

## Constraints

- **LLM/상품표 재분류 호출 금지.** `assert_no_model_classification_dependencies()` (283행) AST 가드가
  `DB_FinProduct_Map` / `DB_ItemIdAllocator` / `qwen_client` import 및 `call_llm` / `classify_unmapped` /
