# 배민 메뉴명 수집 자동화 (대시보드 + 메뉴 전용 버튼)

## Task

배민 메뉴판 수동수집(`Sites.baemin._collectMenupan`)은 이미 `content/02_baemin.js`에 구현되어 있다.
이제 이것을 **배민 자동수집 대시보드(`runner_baemin.html` / `runner_baemin.js`)에서
전 계정 배치로 돌릴 수 있게** 확장한다.

핵심 요구 2가지:
1. `categories`에 `menupan`을 추가해 주문과 함께 배치 수집한다.
2. **"🍽 메뉴만 수집" 버튼**을 새로 만들어 주문 없이 메뉴관리만 수집하는 모드를 제공한다.
3. 한 계정에 매장(shopId)이 여러 개면(예: 백석점 계정에 `도리당 백석점` + `나홀로 1인 곱도리탕 백석점`)
   **select의 모든 shopId를 순회**해 매장마다 CSV를 만든다.

파일 저장 규칙은 현행 유지 — 매장별 개별 CSV `[브랜드][매장명]baemin_menu_YYYY-MM-DD.csv`.

## Project Conventions

작업 대상은 Airflow 리포가 아니라 **크롬 확장(MV3) 폴더**다.

- 작업 루트: `C:\Users\민준\OneDrive - 주식회사 도리당\Extention\doridang_collector_개발용`
- 지침 원본: 해당 폴더의 `AGENTS.md` (CLAUDE.md는 포인터일 뿐)
- 대시보드 로깅은 `log(text, type)` — `type`은 `'info' | 'ok' | 'err'`
- content script 로깅은 `console.log('[Collector] ...')`

- 주석은 최소화 (WHY만)

### 5. 계정의 shopId 목록 조회 `getShopOptions(tabId)` 신설

메뉴판 페이지의 select는 신형 클래스(`Select_b_ezkn_...`)라 기존 셀렉터로는 안 잡힌다.
**클래스에 의존하지 말고 문서 내 모든 `select`에서 숫자 value 옵션을 긁어 dedupe**한다.
`getShopInfo()`(`:346`) 근처에 추가:

```js
async function getShopOptions(tabId) {
  try {
    const [probe] = await chrome.scripting.executeScript({
      target: { tabId },
      func: () => {
        const textOf = el => (el?.innerText || el?.textContent || '').replace(/\s+/g, ' ').trim();
        const seen = new Map();
        for (const select of document.querySelectorAll('select')) {
          for (const option of select.options) {
            const value = String(option.value || '').trim();
            if (!/^\d{4,}$/.test(value) || seen.has(value)) continue;
            seen.set(value, { storeId: value, text: textOf(option) });
          }
        }
        return [...seen.values()];
      }
    });
    return probe?.result || [];
  } catch (_) { return []; }
}
```

### 6. 메뉴 수집 루프 `collectMenupanForAccount(tabId, i, shopOptions)` 신설

`collectCategory()`(`:674`) 아래에 추가한다. 매장(shopId)마다
"이동 → content 주입 → COLLECT 전송 → BAEMIN_CATEGORY_COMPLETE 대기"를 반복한다.

```js
async function collectMenupanForAccount(tabId, i, shopOptions) {
  setBadge(i, 'menupan', 'run');
  const shops = shopOptions.length ? shopOptions : [];
  if (!shops.length) throw new Error('메뉴 수집 대상 shopId를 찾지 못함');

  let okCount = 0;
  const failNotes = [];

  for (let n = 0; n < shops.length; n++) {
    if (stopRequested) throw new Error('중단됨');
    const shop = shops[n];
    const label = shop.text || shop.storeId;
    setRow(i, { note:`메뉴 ${n + 1}/${shops.length}: ${label}`, current:true });
    log(`  -> 메뉴 이동 [${n + 1}/${shops.length}] ${label} (${shop.storeId})`, 'info');

    await chrome.tabs.update(tabId, { url: urlFor('menupan', shop.storeId) });
    const loaded = await waitUrl(tabId, u => RE_LOGGEDIN.test(u), 30000);
    if (!loaded) { failNotes.push(`${label}: 페이지 이동 실패`); continue; }

    const csReady = await injectContent(tabId);
    if (!csReady) { failNotes.push(`${label}: content script 실패`); continue; }
    await sleepWithStop(2500);   // 메뉴 리스트 최초 렌더 대기

    const waiter = waitForCategory('menupan', COLLECT_TIMEOUT);
    await chrome.tabs.sendMessage(tabId, { type:'COLLECT', source:'batch' });
    const result = await waiter;

    if (result.stopped) throw new Error('중단됨');
    if (result.timeout || result.success === false) {
      const reason = result.timeout ? 'timeout' : (result.error || '수집 실패');
      log(`  -> 메뉴 실패: ${label} (${reason})`, 'err');
      await captureBaeminDebug(tabId, `menupan-${shop.storeId}`);
      failNotes.push(`${label}: ${reason}`);
      continue;
    }

    okCount++;
    log(`  -> 메뉴 완료: ${result.store_name || label} rows=${result.rows || 0} file=${result.filename || '-'}`, 'ok');
    await sleepWithStop(800);
  }

  if (okCount === 0) {
    setBadge(i, 'menupan', 'fail');
    throw new Error(`메뉴 수집 전부 실패 (${failNotes.join(' / ')})`);
  }
  setBadge(i, 'menupan', okCount === shops.length ? 'ok' : 'warn');
  return { okCount, total: shops.length, failNotes };
}
```

### runner_baemin.js — waitForCategory / 응답 수신 (`:308~344`)

```js
function waitForCategory(category, timeoutMs = COLLECT_TIMEOUT) { /* pending = {category,...} */ }

chrome.runtime.onMessage.addListener((msg) => {
  if (msg?.type === 'LIVE_LOG') { log(msg.msg); return; }
  if (!pending || pending.settled) return;
  if (msg?.type === 'BAEMIN_CATEGORY_COMPLETE') {
    const payload = msg.payload || {};
    if (payload.category !== pending.category) return;   // ← category 문자열이 정확히 'menupan'이어야 함
    pending.settled = true; pending.payload = payload;
    clearTimeout(pending._to); clearInterval(pending._poll); pending.resolve(payload);
  }
});
```

### 대상 페이지 특성 (실측)

- 메뉴판 URL: `https://self.baemin.com/shops/{shopId}/menupan`
- 매장 select는 **신형 클래스**(`select.Select_b_ezkn_11w1d6i7`)라
  기존 `select.Select-module__a623` / `.ShopSelect-module___pC1` 셀렉터로 잡히지 않는다.
  → `getShopOptions`는 클래스 대신 `document.querySelectorAll('select')` + 숫자 value로 판별한다.
- option 텍스트 예: `[음식배달] 닭도리탕 전문 도리당 백석점 / 찜·탕·찌개 14168464`
- 한 계정에 브랜드가 다른 매장이 섞여 있다(`도리당` / `나홀로 1인 곱도리탕` / `오늘은전골`).
- 메뉴 리스트는 가상 스크롤이라 수집에 매장당 수십 초가 걸릴 수 있다 → `COLLECT_TIMEOUT`(240초) 유지.

10. **회귀** — `▶ 선택 수집`으로 주문만 돌던 기존 동작 확인(8번에서 겸사 확인) →
    기대: 주문 수집 로직·어제 날짜 처리에 변화 없음

## Verification Loop

```
LOOP until all PASS:
  1. Test Cases 1~10 순서대로 실행
  2. FAIL 항목 → 원인 분석
     - 4번에서 응답 없이 timeout → payload.category 불일치 의심.
       content/02_baemin.js:29의 category 문자열이 'menupan'인지, 대시보드도 'menupan'을 쓰는지 대조
     - 5번 FAIL(CSV 1개만) → getShopOptions가 빈 배열.
       메뉴판/홈 페이지 콘솔에서 확인:
       [...document.querySelectorAll('select')].map(s => [...s.options].map(o => o.value))
     - 6번 FAIL → collectMenupanForAccount의 okCount 분기(ok/warn/fail) 확인
     - 7번 FAIL → 루프 안에서 sleep 대신 sleepWithStop을 쓰는지 확인
  3. 코드 수정 (runner_baemin.js / runner_baemin.html)
  4. node --check → 확장 리로드 → 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

## Constraints

- **`content/02_baemin.js`는 수정하지 않는다.** 이미 menupan 라우팅과 저장이 완성돼 있다.
  대시보드에서 동작하지 않는다면 원인은 대시보드 쪽 category 문자열/타이밍이다.
- 카테고리 키 문자열은 반드시 **`'menupan'`** (`'menu'`로 쓰면 `waitForCategory`가 영원히 대기한다).
- 기존 `menuBtn`("배민 열기")과 새 `menuOnlyBtn`을 혼동하지 않는다. 기존 버튼 동작 변경 금지.
- 주문 수집 로직(어제 날짜, `selectTargetStore`, `_isDashboardBatchOrders` 관련 규약)은 건드리지 않는다.
- 메뉴 수집 루프 안의 대기는 전부 `sleepWithStop` — 중단 버튼이 매장 사이에서 먹혀야 한다.
- 한 매장이 실패해도 다음 shopId로 계속 진행한다(전부 실패일 때만 계정을 fail 처리).
- `*-DESKTOP-*` 백업 파일은 읽지도 수정하지도 않는다.
- 전체 병합 CSV는 만들지 않는다. 매장별 개별 CSV만 저장한다(현행 유지).
- OneDrive 폴더를 수정하므로 진행 전 사용자 승인을 받는다 (확장 폴더 `AGENTS.md` 규칙).
