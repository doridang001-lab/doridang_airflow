# 배민 정산정보 미수집 수동 백필 및 재발 방지

## Task

배민 주문상세의 "정산정보" 블록(주문중개·고객할인비용·배달·그외·부가세·**입금예정금액**) 수집이
2026-07-28부터 무너져(수집률 100% → 4~30%), `delivery_commission` 마트의 배민 `settlement_amount`가
음수(-3,000)·0으로 적재되고 수수료율이 100%로 나온다. 원인은 `DB_Beamin_04_orders.py`의
행 펼침 후 고정 `time.sleep(0.3)` 대기(정산정보는 지연 렌더됨)다.
확장프로그램으로 수동 재수집한 CSV를 `DB_CollectionCompare_Dags` 경로로 안전하게 적재할 수 있도록
가드를 넣고, 마트가 미수집을 "정산 0원"으로 확정하지 않게 고치고, 수집 자체를 복구한다.

## Implementation Steps

### 1. 적재 가드 — `DB_BaeminManual_load.py` (백필 선행 필수)

현재 `_replace_manual_orders`는 파일이 커버하는 min~max **연속 구간의 기존 행을 통째로 지우고**
새 행으로 대체한다. `replace_covered_date_range`가 `shrunk_dates` / `partial_shrunk_dates`를
계산해 주지만 `_load_one_file`은 **경고 로그만 남기고 그대로 덮는다**.
77개 매장을 일괄 투입하면 수집이 덜 된 파일 하나가 그 매장 9일치를 깎아먹는다.

- `_load_one_file`의 월별 루프에서 `_replace_manual_orders` 호출 후,
  `info["shrunk_dates"]` 또는 `info["partial_shrunk_dates"]`가 비어있지 않으면
  **`write_table` 호출 없이 그 파일 전체를 skip**하고 `return 0, False`.
  `ok=False`면 `cleanup_manual_baemin_files`가 `_archived`로 옮기지 않으므로 재작업 대상이
  폴더에 그대로 남는다. 이미 `write_table`을 마친 앞선 ym이 있으면 그대로 두되 warning에 명시.
- warning 문구에 `brand/store/ym`, `info["shrink_details"]`(날짜별 existing_orders / new_orders)를 남긴다.
- **정산 후퇴 방지**: 신규 파일의 어떤 날짜에서 `입금예정금액`이 전량 비어 있는데
  기존 파티션 같은 날짜엔 값이 있으면 같은 기준으로 skip. 비교는 `order_date`로 날짜를 맞춘 뒤
  문자열 공백·`"nan"`·`"None"`을 빈값으로 정규화해서 판정한다.
- 우회 수단: `context`의 `dag_run.conf.get("force_shrink")`가 참이면 가드를 건너뛴다.
  `load_manual_baemin_orders(**context)` → `_load_one_file(csv_path, force=...)`로 인자 전달.

### 2. 마트 fix — `DB_DeliveryCommission.py`

백필해도 못 채우는 매장·날짜가 남으므로 마트 자체 방어가 필요하다.

- `_load_baemin_orders_agg`: `grouped["입금예정금액"] = grouped["입금예정금액"].fillna(0)` **삭제**.
  `unsettled` 마스크와 `logger.warning`은 유지. 날짜×매장×브랜드 groupby에 `_unsettled=("_unsettled","max")`를
  추가해 미수집 주문이 1건이라도 있으면 `baemin_deposit_amt = pd.NA`로 만들고 `astype("Int64")`.
  (참고: 260730 스펙이 부분 합산으로 되돌렸던 동작의 재도입이다. 당시 미수집 123행일 땐 부분합이
  나았지만 지금은 7,064건이라 거짓 0이 더 해롭다. 이 근거는 커밋 메시지에 남긴다.)
- **만나서결제 보정**: 필수 컬럼 집합에 `만나서결제금액` 추가, `_money()`로 파싱,
  주문 단위 `max` → 날짜×매장×브랜드 `sum` = `baemin_cash_amt`(음수). 반환 columns에 포함.
  `build_delivery_commission` 배민 분기에서
  `settlement_amount = baemin_deposit_amt - ad_spend - baemin_cash_amt`.
  (현금 주문은 `입금예정금액`이 음수(예: -2,528)라 현금 수령액이 수수료로 잡힌다. 이를 되돌린다.)
- `baemin["settlement_amount"]`의 `.astype("int64")` → `.astype("Int64")`(NA 전파).
  `_finalize`의 `diff_amt = total_amt - settlement_amount`는 그대로 두면 NA가 전파된다.
- `OUTPUT_COLUMNS` 목록·컬럼 순서·`_write_parquet_atomic`·`_finalize`의 키중복/플랫폼/브랜드 검증은
  **절대 변경 금지**(Power BI 소비처). 새 컬럼을 마트에 추가하지 않는다.
- 쿠팡 분기의 우가클 3종 `NA`, 배민 분기의 쿠팡 지표 6종 `NA`는 플랫폼 구분용이므로 손대지 않는다.

### 3. 수집 fix — `DB_Beamin_04_orders.py`

- 신규 JS 상수 `_SETTLE_READY_JS`를 `_EXPAND_ROW_JS` / `_COLLAPSE_ROW_JS` 옆에 추가한다.
  `arguments[0]`은 data-index. `_EXTRACT_SINGLE_ROW_JS`와 **동일 선택자**를 써야 한다:
  형제 TR을 순회해 `td[colspan="9"] .DetailInfo-module__pZYe`를 찾고,
  그 안 `section.DetailInfo-module__Sopx` 중 `.DetailInfo-module__bKQt` 텍스트에 `정산정보`가 있고
  `.FieldItem-module__gYJs`가 1개 이상이면 `true`, 아니면 `false`.
- 신규 헬퍼 `_wait_settle_section(driver, idx, timeout: float = 3.0) -> bool`:
  0.15초 간격 폴링. 예외는 기존 규약대로 `_is_crash(exc)`면 `OrdersCollectionInterrupted`로 승격.
- `_collect_all_pages` 행 루프에서 `driver.execute_script(_EXPAND_ROW_JS, idx)` 다음의
  `time.sleep(0.3)`을 `_wait_settle_section(driver, idx)` 호출로 교체.
  False면 `_COLLAPSE_ROW_JS` 실행 후 **1회 재-expand + 재대기**, 그래도 False면
  `logger.warning("정산정보 미렌더: %s idx=%s", store, idx)`만 남기고 추출은 진행한다
  (주문정보는 살린다). 행 단위 expand/collapse 구조 자체는 **유지**한다 — Chrome OOM 회피 목적이다.
- `_validate_collected`: 반환 dict에 `settle_rate` 추가.
  `settle_rate = (입금예정금액이 빈값이 아닌 고유 주문번호 수) / (결제금액이 있는 고유 주문번호 수)`,
  분모 0이면 `None`. `matched` 판정식에는 넣지 않는다.
  `_collect_with_retry_on_mismatch`에서 `matched`가 True여도 `settle_rate`가 0.9 미만이면
  `logger.warning`(매장·target_date·비율)을 남기고 **재수집 1회**를 시도한다.
  (현재는 주문건수·금액만 비교해서 정산 6컬럼이 전량 비어도 `matched=True`가 되고,
  그래서 `DB_Beamin_Macro_Dags_Retry`가 9일간 한 번도 재시도하지 않았다.)

  3. 코드 수정
  4. 전체 Test Cases 재실행

## Constraints

- `OUTPUT_COLUMNS` 목록과 컬럼 순서를 변경하지 않는다(Power BI 소비처 있음). 새 마트 컬럼 추가 금지.
- `_write_parquet_atomic`, `_finalize`의 키 중복·플랫폼·브랜드 검증 로직을 완화하지 않는다.
- 쿠팡 분기의 우가클 3종 `NA`, 배민 분기의 쿠팡 지표 6종 `NA`는 플랫폼 구분용이므로 0으로 채우지 않는다.
- `_money` / `_nullable_money` 헬퍼 동작을 바꾸지 않는다(쿠팡 경로가 공유).
- 정산 미수집 `logger.warning`은 삭제하지 않는다 — 미수집 식별 수단이 이 로그뿐이다.
- `_collect_all_pages`의 행 단위 expand/collapse 구조를 "모두 펼치기"로 바꾸지 않는다.
  전 행 동시 펼침은 Chrome OOM crash를 유발해 이 구조가 도입됐다.
- `_SETTLE_READY_JS`의 선택자는 `_EXTRACT_SINGLE_ROW_JS`와 한 글자도 다르면 안 된다.
  어긋나면 대기가 무의미해진다.
- `dags/db/*.py`는 수정하지 않는다. DAG는 오케스트레이션만 둔다.
- 쿠팡 수집(`정산_예정_금액` 99.7%)은 정상이므로 건드리지 않는다.
- 마트 백필은 코드 수정·테스트 통과 이후에만 실행한다. 가드 없이 77개 매장 CSV를 넣으면
