### 1. 조회 0건(자료없음) 정상 종료

1-1. 모듈 상단에 예외 클래스 추가.
```python
class NoDataError(RuntimeError):
    """조회 결과가 0건이라 Excel 내보내기가 발생하지 않은 정상 상황."""
```

1-2. 신규 헬퍼 `_find_blocking_dialog()` — 물류담이 띄운 알림 모달을 찾고 **내부 텍스트를 로그로 남긴다**. 문구를 모르는 상태이므로 한글 문자열 하드코딩 금지, "예상 밖 모달이 떴다 + 실제 텍스트"를 기록하는 것이 목적.
```python
_DIALOG_TITLE_HINTS = ("확인", "알림", "주의", "Information", "Warning", "Error")

def _find_blocking_dialog():
    for window in Desktop(backend="uia").windows():
        title = window.window_text().strip()
        if not title or title.startswith(MAIN_WINDOW_TITLE_PREFIX):
            continue
        if title == ORDER_WINDOW_TITLE or len(title) > 30:
            continue
        if title in _DIALOG_TITLE_HINTS or window.class_name() in ("#32770", "TMessageForm"):
            texts = []
            try:
                for child in window.descendants():
                    text = child.window_text().strip()
                    if text and text not in texts:
                        texts.append(text)
            except Exception:
                pass
            return window, " | ".join(texts[:10])
    return None, ""
```

1-3. `_wait_for_export_workbook(before_keys, timeout_seconds, target_date)` 확장 — 폴링 루프에서 **워크북과 모달을 동시에 감시**한다.
- (a) 새 워크북 발견 → 기존대로 반환
- (b) 모달 발견 → `logger.info("blocking dialog: title=%s text=%s", ...)` 후 그 안의 `확인`/`OK` 버튼 클릭해 닫고 `raise NoDataError(...)`
- (c) 타임아웃 + **대상일이 일요일**(`datetime.strptime(target_date, "%Y%m%d").weekday() == 6`) → `raise NoDataError("no data (Sunday)")` 로 격하
- (d) 타임아웃 + 평일 → 기존 `RuntimeError("export Excel workbook not found")` 유지

1-4. 같은 함수의 fallback 분기 버그 수정. 현재 `:226`에서 `key not in before_keys`면 이미 `return` 하므로 `:229`의 동일 조건은 **도달 불가능한 죽은 코드**다. "기존 워크북에 덮어써지는" 케이스를 잡으려던 원래 의도대로 조건을 바로잡는다.
```python
# before (dead code)
if key not in before_keys and not bool(workbook.Saved):
    fallback = workbook
# after
if key in before_keys and not bool(workbook.Saved):
    fallback = workbook
```

1-5. `run()`에서 `NoDataError`는 성공 취급.
```python
except NoDataError as exc:
    logger.info("no data for %s; graceful exit: %s", date_digits, exc)
    exit_code = 0
```
작업스케줄러 `LastTaskResult`가 0이 되어 오탐 알림이 안 뜬다.

**일요일 하드코딩 스킵은 넣지 말 것.** 일요일에도 실제로 조회를 시도해야 나중에 일요일 영업이 생기면 자동 수집된다. 일요일 판정은 (c)의 타임아웃 격하 용도로만 쓴다.

### 2. 실패해도 반드시 종료 (핵심)

2-1. `_open_order_details_for_date()` 끝의 `_close_mulryudam(timeout_seconds)` 호출(현재 `:397`)을 **제거**한다. 종료 책임을 `run()` 한 곳으로 모은다. `_close_export_workbook(export_workbook)`도 마찬가지로 `run()`의 정리 단계로 옮기되, 워크북 핸들을 밖으로 전달해야 하므로 `_open_order_details_for_date`가 워크북을 반환하거나 mutable holder에 담는 방식 중 하나를 택한다.

2-2. `run()`을 `try / except / finally` 구조로 재구성. `finally`에서 **각 단계를 개별 try/except로 감싸** 어느 하나가 실패해도 다음 단계가 실행되게 한다.
```
finally:
    1) export 워크북이 열려 있으면 _close_export_workbook()  (SaveChanges=False, Workbooks.Count==0이면 Quit)
    2) _close_mulryudam(timeout_seconds)  best-effort
    3) ENT- 창이 아직 남아 있으면 _force_kill_mulryudam()
```

2-3. 신규 `_force_kill_mulryudam()` — 좌표 클릭 종료가 실패했을 때의 최후 수단.
```python
import subprocess
import win32process

def _force_kill_mulryudam() -> None:
    try:
        window = _find_window_by_title_prefix(MAIN_WINDOW_TITLE_PREFIX, 3)
    except RuntimeError:
        return
    _, pid = win32process.GetWindowThreadProcessId(window.handle)
    logger.warning("force kill Mulryudam pid=%s", pid)
    subprocess.run(["taskkill", "/PID", str(pid), "/F", "/T"], capture_output=True)
```

## Constraints

- **일요일 하드코딩 스킵 금지**. 일요일에도 조회를 시도해야 한다(사용자 결정). 일요일 판정은 타임아웃 시 `NoDataError` 격하 용도로만 사용.
- **`modules/transform/utility/notifier.py` 수정 금지.** 그대로 import해 쓴다.
- **작업스케줄러 재등록 금지.** `register_mulryudam_login_confirm_task.ps1`은 손대지 않는다.
- **신규 파일 생성 금지.** 모든 변경은 `mulryudam_login_confirm.py` + `.env` + `.env.example` 안에서 끝낸다.
- 텔레그램 토큰 값을 `.env.example`·로그·커밋에 절대 넣지 않는다.
- `finally` 정리 단계는 각각 개별 `try/except`로 감싼다. 정리 중 예외가 원래 예외를 덮어쓰면 안 된다.
- `print` 금지, 전부 `logger`.
- 검증 통과 후 `scripts/mulryudam_login_confirm.py`와 `scripts/register_mulryudam_login_confirm_task.ps1`은 현재 **git untracked** 상태이므로 새 브랜치를 만들어 커밋한다(현재 브랜치 `fix/gitpush-pathspec`와 무관).

## Do Not Ask — Decide Yourself

- 파일이 이미 존재하면: 덮어쓰기
- import가 모호하면: Reference Code의 패턴 따라가기
- 타입 힌트 여부: 기존 파일과 동일하게 (`from __future__ import annotations`, `X | None`)
- 주석 여부: 최소화 (WHY만, WHAT 설명 금지)
- 변수명·함수명 스타일: snake_case, private helper는 `_` 접두 (기존 파일과 동일)
- 모달 감지 헬퍼가 실제 물류담 알림창을 못 잡으면: 일요일 타임아웃 격하(1-3 (c))가 안전망이므로 그대로 진행하고, 로그의 `visible window:` 덤프를 근거로 `_DIALOG_TITLE_HINTS`를 보강
