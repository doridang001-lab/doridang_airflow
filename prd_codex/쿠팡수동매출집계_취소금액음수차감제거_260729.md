# 쿠팡수동 매출집계 교정 — 취소주문 `-취소금액` 음수 차감 제거 (Σ매출액으로 통일)

## Task
`unified_sales`의 쿠팡수동(TEST_STORES 25개 매장) 매출이 실제보다 작게 집계된다. 원인은 전체취소 주문을 `-취소금액`으로 **마이너스 계상**하는 로직(`DB_UnifiedSales_coupang.py` `_transform_to_unified`, `DB_DeliveryCommission.py` `_load_coupang_orders_agg`)이다. 쿠팡 정산 `매출액`은 전체취소=0, 부분취소=차감 후 순액을 이미 담고 있으므로 **주문 매출 = Σ매출액** 하나로 통일한다. 전 기간 33 store-day가 음수로 저장돼 있고 총 **20,762,000원**이 과소계상됐다.

> `prd_codex/쿠팡취소주문매출처리교정_260713.md`에서 이미 "취소=0, 매출액 기준" 규칙을 세웠으나, 이후 `취소금액` 컬럼이 추가되며 `-취소금액` 차감이 재도입되어 회귀했다. 이번 작업은 그 규칙의 복원 + 부분취소 명문화 + DeliveryCommission 동반 교정 + 전 기간 백필이다.

- 예외 2건: 삼송점 07-21(수동 188,800 vs toorder 290,000)은 부분수집 이슈로 별개(이미 partial 마커가 감지 중), 동탄영천점 07-24는 `매출액` 미파싱 주문이 있어 **`total_price` 폴백이 있어야** toorder(791,800)와 일치.

### 1. `DB_UnifiedSales_coupang.py` `_transform_to_unified` (약 397-432행)

`cancel_amount` 시리즈(405-412행)를 **삭제**하고, 주문별 루프의 금액 분기를 아래로 교체한다.

```python
    maechul = (
        pd.to_numeric(
            df["매출액"].astype(str).str.replace(",", "", regex=False).str.strip(),
            errors="coerce",
        )
        if "매출액" in df.columns
        else pd.Series(float("nan"), index=df.index)
    )
    fallback_amount = pd.to_numeric(df["total_price"], errors="coerce").fillna(0)
    out["order_cnt"] = 0
    for order_id, group in out.groupby("order_id", sort=False):
        if group.empty:
            continue
        idx = group.index[0]
        indices = group.index
        is_cancel = bool(out.loc[indices, "sale_type"].eq("취소").any())
        order_sales = maechul.loc[indices]
        # 쿠팡 정산 `매출액`은 부분취소가 이미 차감된 순액이고 전체취소는 0/결측이다.
        # `취소금액`을 추가로 빼면 이중 차감이 되어 일매출이 음수로 떨어진다.
        if order_sales.notna().any():
            amount = order_sales.fillna(0).sum()
        elif is_cancel:
            amount = 0
        else:
            amount = fallback_amount.loc[indices].iloc[0]
        out.at[idx, "total_price"] = int(amount)
        out.at[idx, "order_cnt"] = 0 if is_cancel else 1
```

- `order_cnt` 규칙(취소 0건 / 정상 1건)은 현행 유지.
- `total_price` 폴백은 **정상 주문에만** 적용. 정산 미파싱 취소주문에 폴백을 태우면 취소액이 매출로 잡힌다.
- `sale_type`(정상/취소) 라벨 자체는 그대로 남겨 취소 이력 추적 가능하게 둔다.
- `취소금액` 컬럼은 이 함수에서 더 이상 읽지 않는다.

def _money(series: pd.Series) -> pd.Series:
    return _nullable_money(series).fillna(0)


def _nullable_money(series: pd.Series) -> pd.Series:
    return pd.to_numeric(
        series.astype(str).str.replace(",", "", regex=False).str.strip(),
        errors="coerce",
    )

## Constraints
- **`취소금액`으로 매출을 차감하지 않는다.** 부분취소는 `매출액`에 이미 반영돼 있고, 전체취소는 `매출액=0`이다. 이 규칙을 코드 주석으로 남겨 재회귀를 막을 것.
- `total_price` 폴백은 **정상 주문에만** 적용. 취소주문에 폴백을 태우면 취소액이 매출로 잡힌다.
- `order_cnt` 규칙(취소 0 / 정상 1)은 변경하지 않는다.
- `sale_type` 라벨(정상/취소)은 계속 기록한다 — 취소 이력 추적용.
- `DB_CoupangMacro_load.py`(원천 적재), `DB_Coupang_02_validate.py`(레거시 CSV 경로, 현재 미동작), `DB_CollectionCompare.py`는 건드리지 않는다.
- 배민(`DB_UnifiedSales_baemin.py`) 경로는 이번 범위 밖 — `주문상태 == "배달완료"` 필터와 `_parse_baemin_amount_series` 유지.
- 삼송점 2026-07-21의 toorder 대비 -101,200 갭은 **부분수집 이슈로 별개**다. 이번 수정으로 맞추려 하지 말 것 (이미 partial 마커가 감지 중).
- 원천에 `store=구로디지털점` / `store=구로디지털단지점`처럼 매장 개명으로 파티션이 갈라진 케이스가 있다. `_read_coupang_month`가 `store={store}` 정확 매칭이라 구파티션이 안 읽히는 별개 이슈이며, **이번 범위 밖**이다.
