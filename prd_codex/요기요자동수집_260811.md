# 요기요 자동수집 (계정별 반복)

## Task

크롬 확장 `doridang_collector_개발용`에 **요기요 정산 엑셀 자동수집 대시보드**를 추가한다.
쿠팡(`runner.html`) · 배민(`runner_baemin.html`) · 네이버(`runner_naver.html`) 대시보드는 이미 있고 요기요만 없다. `accounts.js`에 요기요 계정이 67행(고유 id 63개) 들어 있어 지금은 사람이 하나씩 로그인해서 받고 있다.
요기요는 DOM 스크랩이 아니라 **사이트가 엑셀을 직접 내려주는** 구조라, 계정마다 아래 4단계만 반복하면 된다.

1. 요기요 로그인 (`content/04_auto_login.js`의 `platform === 'yogiyo'` 분기 — **이미 구현되어 있음, 수정 금지**)
2. `https://ceo.yogiyo.co.kr/tax-invoice/settlement` 이동
3. `<div size="32" color="gray200C" class="sc-dkzDqf jFXduo">` 클릭
4. `<div size="40" color="primaryA" class="sc-dkzDqf loPEuy">` (다운로드) 클릭 → 파일 저장 확인

**기간(월) 설정은 이번 범위에서 하지 않는다.** 페이지 기본 조회기간 그대로 받는다. (나중에 필요해지면 `<div size="48" class="Overlay-sc-x5407x-0 bXWNvG">` 오버레이를 다루면 된다 — 상수와 주석만 남긴다.)

## Project Conventions

- 이 프로젝트는 **Chrome MV3 확장 (순수 JS)** 이다. Python/Airflow 규칙은 적용되지 않는다.
- 답변·로그·주석은 한글.
- 대시보드(runner) = 확장 페이지 → `chrome.tabs` / `chrome.scripting` / `chrome.downloads` 사용 가능.
  콘텐츠 스크립트 = 페이지 DOM만 담당 → `chrome.runtime.sendMessage`로만 대시보드와 통신.
- 콘텐츠 스크립트는 `content/00_config.js`가 만든 전역 `Sites` / `Utils` 객체에 등록한다. 로딩 순서가 manifest 배열 순서다.
- manifest `content_scripts`는 `all_frames: true` → 새 모듈은 **반드시 `if (window.top !== window) return;` 가드**를 넣는다.
- 진행 로그는 `chrome.runtime.sendMessage({type:'LIVE_LOG', msg})`, 완료 통보는 전용 타입(`YOGIYO_COMPLETE`).
- 기존 수동수집(팝업·단축키·확장아이콘 = `source:'manual'`)과 대시보드 배치수집(`source:'batch'`)의 분리를 깨뜨리지 않는다.
- **금지**: `*-DESKTOP-*.js`, `*.bak_*` 백업 파일 수정 / `accounts.js`·`accounts_data.js` 수정(자동생성) / 쿠팡·배민·네이버 기존 로직 변경.
- 검증은 `node --check <파일>`.

`collect(opts)` 흐름:
1. `if (window.top !== window) return;`
2. 1단계 대상 요소가 보일 때까지 폴링(최대 30초, 500ms 간격). 못 찾으면 `SELECTOR_NOT_FOUND` 실패.
3. 1단계 클릭 → 1.5~2초 대기 → 2단계(다운로드) 클릭
4. `_sendComplete({ success:true, clicked:['filter','download'] })`. 단계별로 `_sendLiveLog`.
5. 예외는 전부 잡아 `_sendComplete({ success:false, errorCode:'COLLECT_ERROR', error })`.

**셀렉터 해석기 `_resolveIcon(spec)`** — styled-components 해시(`jFXduo`, `loPEuy`)는 요기요 배포마다 바뀌므로 다단계로 찾는다:
1. `div[size="32"][color="gray200C"]` (속성 기반, 해시 무관 — 1순위)
2. `.sc-dkzDqf.jFXduo` (사용자가 준 정확한 클래스 — 2순위)
3. 둘 다 실패하면 화면에 보이는 `div[size]` 후보들의 `class / size / color / 가까운 조상 텍스트`를 `LIVE_LOG`로 덤프하고 `SELECTOR_NOT_FOUND` 실패
   → 셀렉터가 바뀌었을 때 로그만 보고 1순위 값을 고칠 수 있어야 한다.

다운로드 버튼도 동일: `div[size="40"][color="primaryA"]` → `.sc-dkzDqf.loPEuy`.

가시성 판정은 아래 `_isVisible` 패턴을 그대로 쓴다(Reference Code 참고).

**클릭 방식**: 아이콘 div 자체가 아니라 `el.closest('button, [role="button"], a') || el` 로 승격한 뒤
`pointerdown → pointerup → click` 순으로 발생시킨다(`bubbles:true`). 아이콘 div만 클릭하면 상위 핸들러가 안 걸리는 경우가 있다.

`loadQueue()`:

`processAccount(i, tabId)` — 계정당:
1. **세션 초기화** (체크박스 기본 ON):
   `chrome.browsingData.remove({origins:['https://ceo.yogiyo.co.kr']}, {cache:true,cookies:true,localStorage:true,indexedDB:true,serviceWorkers:true})`
   → 요기요는 세션이 남으면 **직전 계정 파일이 그대로 다시 받아진다**. 사실상 필수 단계.
2. `navigateAndWait(tabId, LOGIN_URL, u => true, 25000)` → `injectContent(tabId)` → `AUTO_LOGIN {platform:'yogiyo', id, pw, storeName:stores[0], autoClick:true}`
3. **로그인 성공 판정 = 로그인 URL을 벗어남** (`!RE_LOGIN.test(url)`, 최대 60초 폴링). 실패 문구는 `getLoginFailure(tabId)` 패턴(Reference Code) 재사용.
4. background에 파일명 예약: `chrome.runtime.sendMessage({type:'YOGIYO_EXPECT_DOWNLOAD', store: 라벨, accountId: acc.id})`
5. `navigateAndWait(tabId, SETTLEMENT_URL, u => RE_SETTLEMENT.test(u), 30000)` → `injectContent` → `chrome.tabs.sendMessage(tabId, {type:'COLLECT', source:'batch'})`
6. `waitForComplete(120000)` — `YOGIYO_COMPLETE` 대기. `waitForCategory` 패턴 그대로.
7. **파일 저장 확인**: background의 `YOGIYO_DOWNLOAD_SAVED`를 최대 60초 대기. 못 받으면 `chrome.downloads.search({limit:5, orderBy:['-startTime']})`로 한 번 더 확인. 그래도 없으면 **실패 처리**(클릭은 됐는데 파일이 안 떨어진 케이스를 성공으로 세지 않기 위함). 성공 시 저장 파일명을 행에 표시.
8. 실패 시 `YOGIYO_CLEAR_DOWNLOAD`로 예약 해제. 다음 계정 전 3~8초 랜덤 대기.

배치 컨트롤(배민 러너와 동일하게):
- 선택 수집 / 상위 50% / 하위 50% / 재시도(실패분만) / 중단 / 로그 저장 / 요기요 열기
- `indicesForMode(mode)` + `runBatch(mode)` 구조 복제
- 중단은 `stopRequested` 플래그 + `chrome.storage.local[RUNNER_STOP_KEY]` 래치
- URL 파라미터 `?auto=1`, `?store=`, `?q=` 지원(나중에 작업 스케줄러 무인 실행용)
- 전부 성공 + 중단 없음이면 작업 탭 닫기, 아니면 확인용으로 유지

### 4. `background.js` 수정 — 요기요 다운로드 리네임

현재 `onDeterminingFilename`은 확장이 만든 data: URL(`pendingDownloadNamesByUrl`)만 처리하고 나머지는 `return`한다. 요기요는 **사이트가 직접 내려주는 파일**이라 60여 계정이 같은 이름으로 겹친다. 다음을 **덧붙인다**(기존 CSV 경로는 그대로 유지):

```js
let pendingYogiyoDownload = null; // { store, accountId, ts }
const YOGIYO_RESERVE_TTL_MS = 5 * 60 * 1000;
```

- 메시지 `YOGIYO_EXPECT_DOWNLOAD {store, accountId}` → 예약 저장. `YOGIYO_CLEAR_DOWNLOAD` → 해제.
- `onDeterminingFilename`에서 기존 매핑이 없고
  `(downloadItem.url + downloadItem.referrer)`에 `yogiyo.co.kr`이 있고 예약이 TTL 안이면:
  - `yogiyo_settlement_{safeFilenamePart(store)}_{YYYYMMDD}.{ext}` 로 `suggest({filename, conflictAction:'uniquify'})`
  - `ext`는 `downloadItem.filename`의 확장자, 없으면 `xlsx`
  - 매장 여러 개인 계정은 러너가 이미 `A 외 2개` 라벨로 보내므로 그대로 `safeFilenamePart` 처리
- 리네임 직후 `chrome.runtime.sendMessage({type:'YOGIYO_DOWNLOAD_SAVED', filename, downloadId: downloadItem.id})` 후 예약 해제.
- 기존 `safeFilenamePart()`, `pad2()` 재사용.

Sites['naver'] = {
  name: '네이버 스마트플레이스',
  match: (url) => url.includes('new.smartplace.naver.com') && url.includes('/statistics'),

      // ... 수집 ...
      this._sendComplete({ success: true, /* ... */ });

  _isVisible(element) {
    if (!element || !element.isConnected || element.closest('[aria-hidden="true"]')) return false;
    const style = getComputedStyle(element);
    return style.display !== 'none' && style.visibility !== 'hidden' && style.opacity !== '0' && element.getClientRects().length > 0;
  },

  _sendLiveLog(msg) {
    try {
      const result = chrome.runtime.sendMessage({ type: 'LIVE_LOG', msg });
      if (result?.catch) result.catch(() => {});
    } catch (_) {}
  },

  _sendComplete(payload) {
    try {
      const result = chrome.runtime.sendMessage({ type: 'NAVER_STAT_COMPLETE', payload });
      if (result?.catch) result.catch(() => {});
    } catch (_) {}
  }

### runner_baemin.js — 세션 초기화 / 로그인 실패 감지 / 완료 대기 (구조 복제 대상)

```js
async function clearSession() {
  return new Promise(resolve => {
    chrome.browsingData.remove({ origins: ['https://self.baemin.com', 'https://biz-member.baemin.com'] }, {
      cache: true, cookies: true, fileSystems: true, indexedDB: true, localStorage: true, serviceWorkers: true, webSQL: true
    }, () => resolve());
  });
}

async function getUrl(tabId) {
  try { return (await chrome.tabs.get(tabId)).url || ''; } catch (_) { return ''; }
}

async function injectContent(tabId) {           // PING → 실패 시 executeScript 주입, 5회 재시도
  for (let attempt = 1; attempt <= 5; attempt++) {
    try { const resp = await chrome.tabs.sendMessage(tabId, { type:'PING' }); if (resp?.success) return true; } catch (e) {}
    await waitTabComplete(tabId, 10000);
    try {
      await chrome.scripting.executeScript({ target:{ tabId }, files:CONTENT_FILES });
      await sleepWithStop(900);
      const resp = await chrome.tabs.sendMessage(tabId, { type:'PING' });
      if (resp?.success) return true;
    } catch (e) { log(`content 주입 실패(${attempt}/5): ${e.message}`, 'err'); }
    await sleepWithStop(1000 + attempt * 500);
  }
  return false;
}

async function getLoginFailure(tabId) {          // 로그인 실패 문구 감지 — 요기요에도 그대로 쓸 수 있다
  const [probe] = await chrome.scripting.executeScript({
    target: { tabId },
    func: () => {
      const textOf = el => (el?.innerText || el?.textContent || '').replace(/\s+/g, ' ').trim();
      const patterns = [/아이디 또는 비밀번호[^.。!]{0,100}/, /로그인(?:에)? 실패[^.。!]{0,100}/];
      const nodes = document.querySelectorAll('[role="alert"], [aria-live], [class*="error" i], [class*="invalid" i]');
      const texts = [...nodes].map(textOf).filter(Boolean); texts.push(textOf(document.body));
      for (const text of texts) for (const p of patterns) { const m = text.match(p); if (m) return m[0].trim().slice(0, 160); }
      return '';
    }
  });
  return probe?.result || '';
}

function waitForCategory(category, timeoutMs = COLLECT_TIMEOUT) {   // 완료 메시지 대기 + 중단/타임아웃 정산
  return new Promise(resolve => {
    const obj = { category, settled:false, payload:{}, resolve, _to:null, _poll:null };
    pending = obj;
    obj._poll = setInterval(() => {
      if (stopRequested && !obj.settled) { obj.settled = true; obj.payload = { stopped:true, success:false, error:'중단됨' };
        clearInterval(obj._poll); clearTimeout(obj._to); resolve(obj.payload); }
    }, 500);
    obj._to = setTimeout(() => {
      if (!obj.settled) { obj.settled = true; obj.payload = { timeout:true, success:false, error:'timeout' };
        clearInterval(obj._poll); resolve(obj.payload); }
    }, timeoutMs);
  });
}
```

### runner_baemin.js — 큐 로딩 (요기요는 여기에 id 그룹핑을 더한다)

async function loadQueue() {
  if (window.accountsReady?.then) { try { await window.accountsReady; } catch(e) {} }
  const acc = window.ACCOUNTS || {};
  const rows = [];
  for (const stores of Object.values(acc)) {
    for (const s of stores) {
      if (s.platform !== 'baemin') continue;     // 요기요는 'yogiyo'
      rows.push({ id:s.id, pw:s.pw, store:s.store });
    }
  }
  queue = rows;
  el.modeLabel.textContent = `총 ${queue.length}개 배민 계정 - 클릭한 매장만 선택 수집`;
  buildRows(); buildFilterList('');

## Test Cases

1. **문법** `node --check content/08_yogiyo.js && node --check runner_yogiyo.js && node --check background.js && node --check popup.js` → 기대: 출력 없음(에러 0)
2. **manifest JSON 유효성** `node -e "JSON.parse(require('fs').readFileSync('manifest.json','utf8'))"` → 기대: 에러 없음. `js` 배열에 `content/08_yogiyo.js`가 `07_naver.js` 뒤에 있을 것
3. **확장 로드** `chrome://extensions` → 새로고침 → 기대: 오류 배지 없음
4. **큐 개수** 팝업 → `요기요 전체 자동수집` 클릭 → 기대: 대시보드 상단 `총 63개 요기요 계정`(67행 id 그룹핑 후), 매장 필터 칩이 채워짐
5. **1계정 실전** 필터에서 매장 1개 선택 → 수집 시작 → 기대 라이브 로그 순서:
   `세션 초기화 → 로그인중 → 로그인 완료 → 정산 페이지 이동 → 1단계 클릭 → 다운로드 클릭 → 파일 저장`
   그리고 다운로드 폴더에 `yogiyo_settlement_{매장명}_{YYYYMMDD}.xlsx` 생성
   - `SELECTOR_NOT_FOUND`가 뜨면 로그의 후보 덤프를 보고 `_resolveIcon` 1순위 셀렉터를 보정한 뒤 재실행
6. **3계정 연속** → 기대: 파일 3개의 매장명이 서로 다름(세션 섞임 없음), 실패분만 `재시도` 버튼으로 다시 돎
7. **다운로드 실패 감지** 정산 페이지에서 다운로드가 안 떨어지는 계정 → 기대: 성공이 아니라 `파일 저장 확인 실패`로 표시
8. **회귀** `runner.html`(쿠팡) 1계정, `runner_baemin.html`(배민) 1계정 실행 → 기대: 기존과 동일 동작, 파일명 규칙 변화 없음

## Verification Loop

```
LOOP until all PASS:
  1. Test Cases 1~2 (정적) 실행
  2. 확장 리로드 후 3~5 실행
  3. FAIL 항목 → 라이브 로그의 errorCode(SELECTOR_NOT_FOUND / COLLECT_ERROR / timeout)로 원인 분류
  4. 코드 수정 후 전체 재실행
종료 조건: 1~8 전체 PASS + Constraints 위반 없음
```

## Constraints

- `content/04_auto_login.js`의 요기요 분기는 이미 동작한다 — **수정 금지**.
- 쿠팡/배민/네이버 러너 파일과 `content/02_baemin.js`, `content/03_coupangeats.js`, `content/07_naver.js`는 **읽기만** 하고 수정하지 않는다.
- `accounts.js`, `accounts_data.js`는 자동생성 파일 — 수정 금지. 계정 목록 전체를 로그나 출력에 덤프하지 않는다(ID/PW 포함).
- `*-DESKTOP-*`, `*.bak_*` 백업 파일은 건드리지 않는다.
- `background.js`의 기존 `DOWNLOAD_CSV` / `BATCH_FILE_SAVED` 경로는 그대로 둔다. 요기요 분기는 기존 `return` 이후에 **덧붙이는** 형태여야 한다.
- 세션 초기화 체크박스는 기본 ON. 끄는 옵션은 남기되 기본값을 바꾸지 않는다(계정 섞임 방지).
- 기간(월) 선택 UI는 이번 범위 밖. `PERIOD_OVERLAY_SELECTOR` 상수와 주석만 남긴다.
- Airflow 인제스트 DAG 연결은 이번 범위 밖.
