```python
def _attach_profit_sales_base(left_joined: pd.DataFrame) -> pd.DataFrame:
    """수익 계산용 매출. 할인으로 0원이 된 라인은 손실이므로 음수로 잡는다."""
    out = left_joined.copy()
    total = pd.to_numeric(out.get("total_price", pd.Series("", index=out.index)), errors="coerce").fillna(0)
    discount = pd.to_numeric(out.get("discount_amount", pd.Series("", index=out.index)), errors="coerce").fillna(0)
    out[PROFIT_SALES_COLUMN] = (total.where(total.ne(0), -discount)).map(_format_number)
    return out
```

## Verification Loop

구현 완료 후 아래 루프를 **모든 Test Cases PASS까지** 반복한다.

```
LOOP until all PASS:
  1. Test Cases 1~5 (정적 검증) 실행 → 전부 PASS 후에만 6번으로
  2. Test Case 6 (파이프라인 실행) — 사용자 승인 후 실행
  3. Test Cases 7~12 (산출물 검증) 실행
  4. FAIL 항목 → 원인 분석
  5. 코드 수정
  6. 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

**FAIL 시 우선 확인 지점**

## Do Not Ask — Decide Yourself

- 파일이 이미 존재하면: 덮어쓰기
- import가 모호하면: Reference Code의 패턴 따라가기
- 타입 힌트 여부: 기존 파일과 동일하게 (`-> pd.DataFrame`, `str | None` 스타일)
- 주석 여부: 최소화 (WHY만, WHAT 설명 금지) — 기존 파일의 한글 주석 톤 유지
- 변수명·함수명 스타일: snake_case, 내부 헬퍼는 `_` 접두, 기존 파일과 동일하게
- 새 상수 위치: 관련 기존 상수 블록 바로 아래 (`PROFIT_SALES_COLUMN`은 `ADJUSTED_SALES_COLUMN` 옆,
  `CHICKEN_RATIO_SOURCE_*`는 기존 출처 상수 옆)
- 라인 번호는 파일이 커서 어긋날 수 있다. **함수명으로 찾아서** 수정할 것.
