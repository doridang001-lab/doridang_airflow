# 배민수동 item_id 배정 실패 수정

## Task

`DB_UnifiedSales.reconcile_baemin` 태스크가 2026-07-23 실행에서 `ValueError: 배민수동 item_id 배정 실패: store/item_name 필수`로 계속 실패한다. 배민 매크로가 주문 리스트 행만 잡고 메뉴 상세를 못 긁은 **부분 수집 행**(주문내역·주문옵션상세가 모두 빈값)이 원천 parquet에 1건 남아 있어, `item_name=""`인 행이 `allocate_manual_item_ids`의 가드에 걸린다. 원천 데이터가 그대로라 재시도해도 계속 실패한다.

해당 행의 매출(22,300원)을 유실시키지 않으면서 태스크가 죽지 않도록, item_name이 빈 행을 플레이스홀더(`메뉴미상(배민)`)로 채운다. OKPOS가 이미 쓰는 `정산차액(OKPOS)` 패턴과 동일한 방식이다.

```python
MANUAL_UNKNOWN_ITEM_NAME_FMT = "메뉴미상({label})"


def fill_missing_item_name(
    item_name: pd.Series,
    *,
    label: str,
    store: str,
    sale_date: pd.Series | str | None = None,
    order_id: pd.Series | None = None,
) -> pd.Series:
    """수집 결손으로 item_name이 빈 행을 플레이스홀더로 채운다.

    배민/쿠팡 매크로가 주문 행은 잡았지만 메뉴 상세를 못 긁은 경우가 있다.
    이 행을 드롭하면 주문 결제금액이 통째로 사라져 POS 대사에서 불일치가 나므로,
    이름만 채워서 매출을 보존하고 결손 사실은 WARNING으로 남긴다.
    """
    filled = item_name.fillna("").astype(str).str.strip()
    missing = filled.eq("") | filled.str.lower().eq("nan")
    if not missing.any():
        return filled

    placeholder = MANUAL_UNKNOWN_ITEM_NAME_FMT.format(label=label)
    filled = filled.mask(missing, placeholder)

    if order_id is not None:
        order_ids = sorted({str(v).strip() for v in order_id[missing] if str(v).strip()})
    else:
        order_ids = []
    if isinstance(sale_date, pd.Series):
        dates = sorted({str(v).strip() for v in sale_date[missing] if str(v).strip()})
        date_label = ",".join(dates)
    else:
        date_label = str(sale_date or "")

    logger.warning(
        "%s 메뉴 상세 결손 행 플레이스홀더 처리: store=%s date=%s | %d건 order_id=%s",
        label,
        store,
        date_label,
        int(missing.sum()),
        ",".join(order_ids) if order_ids else "-",
    )
    return filled
```

def _transform_to_unified(df, store: str, brand: str, store_map: dict) -> pd.DataFrame:
    """baemin_macro rows -> UNIFIED_COLUMNS DataFrame."""
    df = df[df["주문상태"].fillna("").astype(str).str.strip().eq("배달완료")].copy()
    if df.empty:
        return pd.DataFrame(columns=UNIFIED_COLUMNS)

    out = pd.DataFrame(index=df.index)
    out["sale_date"] = df["sale_date"]
    out["ym"] = df["sale_date"].str[:7]
    out["source"] = BAEMIN_SOURCE
    out["brand"] = brand
    out["store"] = store
    out["platform"] = BAEMIN_PLATFORM
    out["order_id"] = df["주문번호"].fillna("").astype(str).str.strip()
    out["order_time"] = df["order_time"]
    out["sale_type"] = df["주문상태"].map(lambda v: "취소" if "취소" in str(v) else "정상")
    out["order_type"] = df["수령방법"].map(lambda v: "배달_포장" if str(v).strip() == "포장" else "배달")
    out["menu_name"] = (
        df["주문내역"].fillna("").astype(str)
        .str.replace(r"\s*외\s*\d+건$", "", regex=True)
        .str.strip()
    )
    option_name = df["주문옵션상세"].fillna("").astype(str).str.strip()
    is_price = option_name.str.fullmatch(r"[\d,]+")
    out["item_name"] = option_name.mask(is_price, out["menu_name"])   # ← 여기서 빈값 발생
    out["qty"] = _to_int_series(df["주문수량"]).replace(0, 1)
    out["unit_price"] = _to_int_series(df["주문옵션금액"])
    out["discount_amount"] = 0
    out["item_seq"] = out.groupby("order_id").cumcount().add(1).astype(int).astype(str)
    out["item_total"] = out["unit_price"] * out["qty"]
    order_item_sum = out.groupby("order_id")["item_total"].transform("sum")
    order_amount = _first_nonzero_by_order(out["order_id"], _parse_baemin_amount_series(df["결제금액"]))
    out["total_price"] = ((out["item_total"] / order_item_sum.replace(0, 1)) * order_amount).round().astype(int)
    order_sum = out.groupby("order_id")["total_price"].transform("sum")
    residual = order_amount - order_sum
    idx_max = out.groupby("order_id")["item_total"].idxmax()
    out.loc[idx_max, "total_price"] = out.loc[idx_max, "total_price"] + residual.loc[idx_max]
    out["item_id"] = allocate_manual_item_ids(
        out[["source", "brand", "store", "item_name", "unit_price"]]
    )

## Constraints

- `DB_ItemIdAllocator.py`의 `ValueError` 가드를 완화하거나 제거하지 말 것. 데이터 결손은 호출부에서만 처리한다.
- 결손 행을 **드롭하지 말 것**. `total_price` 배분 로직상 이 행이 주문 결제금액 전액을 받아가므로, 드롭하면 매출이 통째로 사라지고 `validate_sales` POS 대사에서 불일치가 난다.
- 플레이스홀더 치환은 반드시 `logger.warning`을 남긴다. 조용히 넘어가면 수집 누락을 영영 추적할 수 없다.
- 배민 `_transform_to_unified`에서 `out["sale_date"]`, `out["order_id"]` 할당 순서를 바꾸지 말 것 (헬퍼가 이 두 컬럼에 의존).

## 후속 구현: FinProduct 전체 연결

`메뉴미상(배민/쿠팡)`은 격리하지 않고 정식 대체 상품으로 연결한다.

- 일반 상품의 map 대상은 `송파삼전점`, `역삼점`으로 유지한다.
- `배민수동/쿠팡수동`의 정확한 `메뉴미상(배민/쿠팡)` 상품만 전 매장에서 map 대상에 포함한다.
- allocator가 발급한 `item_id`와 `exclude_check=N`을 유지한다.
- 표준명은 채널명을 포함한 원래 이름, 분류는 `기타`, 검수 상태는 승인, `classified_by=rule`로 고정한다.
- 해당 행은 LLM 대상에서 제외하고 `fin_product_map_join.csv`와 `fin_product_mart.csv`에 같은 `item_id`로 연결한다.
- 실행 순서는 UnifiedSales 이후가 되도록 FinProduct Map 09:30, FinProduct 10:00으로 조정한다.

추가 회귀 테스트는 `tests/test_fin_product_manual_unknown_integration.py`에서 전 매장 예외 범위, 규칙 승인, LLM 제외, 조인 키, 상품 마트 보강을 검증한다.
