# 배민/쿠팡 수동 재수집 덮어쓰기 수정

## Task

배민/쿠팡 수동 재수집 CSV를 `Collect_Data/영업관리부_수집`에 다시 넣어도 기존의 잘못된 주문 행이 제거되지 않고 **합쳐진다**. 적재 로직이 "주문번호 단위 합집합"이라 재수집본에 없는 유령 주문이 영구 생존하기 때문. 적재를 **주문일자 [min~max] 구간 통째 교체**로 바꾸고, lookback(14일) 밖 과거분 재수집이 `unified_sales`에 소급 반영되도록 재수집 마커를 도입한다.

### 실측 증거 (기흥테라타워점, `collection_compare.parquet` checked_at 2026-07-24 11:18)

| date | 토더 | 통합 | 배민매크로 | 해석 |
|---|---|---|---|---|
| 2026-06-17 | 131,300 | 109,301 | **153,300** | 유령 주문 22,000 잔존 |
| 2026-07-09~07-15 | 정상 | **낮음** | 정상 | parquet은 고쳐졌으나 unified 미반영 |
| 2026-06-25~06-30 | 정상 | 정상 | **낮음** | 6월은 재수집 안 함 (원천 부족) |

`brand=도리당/store=기흥테라타워점/ym=2026-06/orders_2026-06.parquet` 의 06-17 상세:

```
collected_at=2026-06-19T04:18  주문번호 T2DT000030SS  22,000   <- 유령 (06-29 재수집본에 없음)
collected_at=2026-06-29T15:26  주문번호 5건          131,300  <- 재수집 정상분
```

`153,300 = 131,300 + 22,000` — 재수집본에 없는 주문번호가 제거되지 않았다.

### 원인 3가지

1. **적재가 합집합이다.**
   - `DB_Beamin_04_orders.py:1527 _save_orders_csv` — 기존 행 중 **새 주문번호와 일치하는 것만** 제거 후 concat. 재수집본에 없는 주문번호는 영구 생존. (06-17 유령의 실제 발생 경로)
   - `DB_BaeminManual_load.py:53 _upsert_manual_orders` — 주문번호별 `collected_at` 최대값만 남김. 재수집본에 없는 주문번호는 자기 자신이 최대값이라 역시 생존.
   - `DB_CoupangMacro_load.py:233 _load_orders` — concat 후 `ORDER_DEDUP_COLUMNS` dedup만 하므로 동일 문제.
2. **과거분 재수집이 unified_sales로 소급되지 않는다.**
   `DB_UnifiedSales_Dags.py:98 LOOKBACK_DAYS = 14` → `DB_UnifiedSales_baemin.py:342-347`이 최근 14일만 대상. 07-09·6월·1·2월 재수집분은 parquet만 고쳐지고 unified에는 영원히 미반영.
3. **두 DAG가 같은 CSV를 경합한다.**
   `DB_CollectionCompare_Dags.py`(08:20/12:20/15:20)와 `DB_UnifiedSales_Dags.py`(08:37)가 둘 다 `load_manual_baemin_files` + cleanup 실행. 먼저 도는 쪽이 `_archived`로 옮겨서 나중 DAG의 ingest는 항상 빈손 → **XCom 기반 해결 불가**. 그래서 소급 신호는 파일 마커여야 한다.

### 1. `beamin_store_io.py` — 공통 헬퍼 추가

기존 `order_ym()` 아래에 추가한다.

```python
def order_date(series: pd.Series) -> pd.Series:
    """배민 주문시각에서 주문일자(YYYY-MM-DD)를 추출한다. 파싱 실패는 빈 문자열."""
    m = series.fillna("").astype(str).str.extract(r"^\s*(\d{4})\.\s*(\d{1,2})\.\s*(\d{1,2})\.")
    return (m[0] + "-" + m[1].str.zfill(2) + "-" + m[2].str.zfill(2)).fillna("")


def replace_covered_date_range(
    existing: pd.DataFrame | None,
    new_df: pd.DataFrame,
    existing_dates: pd.Series,
    new_dates: pd.Series,
    order_key: str = "주문번호",
) -> tuple[pd.DataFrame, dict]:
    """새 데이터가 커버하는 [min~max] 주문일자 구간의 기존 행을 통째로 버리고 교체한다.

    - 구간 밖 기존 행은 유지
    - 구간 안이지만 새 데이터에 0건인 날짜는 정상적으로 비워짐(취소/영업중단 반영)
    - 날짜 파싱 실패(빈 문자열) 기존 행은 구간 판정 대상이 아니므로 보존

    반환: (combined, info)
      info = {
        "range": (min_date, max_date) | None,
        "removed": int,           # 구간 안에서 버린 기존 행 수
        "covered_dates": [str],   # 구간에 속한 날짜 전체(연속 일자)
        "shrunk_dates": [str],    # 기존 주문>0 인데 신규 주문==0 인 날짜
      }
    """
```

구현 규칙:
- `new_dates`에서 빈 문자열 제외 후 `min`/`max` 산출. 유효 날짜가 하나도 없으면 교체하지 않고 `pd.concat([existing, new_df])` 폴백 + `info["range"] = None`.
- `covered_dates`는 `min`~`max` **연속 일자 전체**(pandas `date_range`)로 만든다. 새 파일에 해당 날짜 데이터가 0건이어도 기존 행을 지워야 하기 때문.
- 유지 대상 기존 행 = `existing_dates`가 빈 문자열이거나 `covered_dates`에 없는 행.
- `shrunk_dates`: 구간 안 각 날짜에 대해 `existing[order_key].nunique() > 0 and new[order_key].nunique() == 0`.
- `existing`이 `None`/빈 DataFrame이면 `(new_df.copy(), info)` 그대로 반환.
- **교체는 항상 수행한다.** `shrunk_dates`는 호출부가 `logger.warning`으로 남기기 위한 신호일 뿐 교체를 막지 않는다.

### modules/transform/pipelines/db/beamin_store_io.py (전체)

```python
"""배민 수집 저장소 IO 헬퍼 — OneDrive 적재는 parquet, 읽기는 parquet 우선·CSV 폴백."""

from __future__ import annotations

import logging
from pathlib import Path

import pandas as pd

logger = logging.getLogger(__name__)

PARQUET_COMPRESSION = "zstd"


def _as_str_df(df: pd.DataFrame) -> pd.DataFrame:
    return df.fillna("").astype(str)


def order_ym(series: pd.Series) -> pd.Series:
    """배민 주문시각에서 주문 월(YYYY-MM)을 추출한다. 파싱 실패는 빈 문자열."""
    matched = series.fillna("").astype(str).str.extract(r"^\s*(\d{4})\.\s*(\d{1,2})\.")
    return (matched[0] + "-" + matched[1].str.zfill(2)).fillna("")


def read_table(stem_path: Path, columns: list[str] | None = None) -> pd.DataFrame | None:
    """확장자 없는 경로(stem)를 받아 parquet 우선·CSV 폴백으로 읽는다. 둘 다 없으면 None."""
    pq = stem_path.with_suffix(".parquet")
    csv = stem_path.with_suffix(".csv")
    if pq.exists():
        return _as_str_df(pd.read_parquet(pq, columns=columns))
    if csv.exists():
        return _as_str_df(pd.read_csv(csv, dtype=str, encoding="utf-8-sig", usecols=columns))
    return None


def write_table(df: pd.DataFrame, stem_path: Path) -> Path:
    """문자열 DataFrame을 parquet(zstd)로 저장하고, 같은 위치의 레거시 CSV는 제거한다."""
    stem_path.parent.mkdir(parents=True, exist_ok=True)
    pq = stem_path.with_suffix(".parquet")
    _as_str_df(df).to_parquet(pq, engine="pyarrow", compression=PARQUET_COMPRESSION, index=False)
    csv = stem_path.with_suffix(".csv")
    if csv.exists():
        try:
            csv.unlink()
        except OSError as exc:
            logger.warning("레거시 CSV 삭제 실패: %s / %s", csv, exc)
    return pq
```

### modules/transform/pipelines/db/DB_BaeminManual_load.py (현행 `_upsert_manual_orders`)

```python
_ORDER_KEY = "주문번호"
_ORDER_LINE_KEY = [
    "주문번호", "주문시각", "주문내역", "주문옵션상세",
    "주문수량", "주문옵션금액", "결제금액",
]


def _upsert_manual_orders(existing: pd.DataFrame | None, new_df: pd.DataFrame) -> pd.DataFrame:
    """기존 월 파티션과 새 수동 CSV를 주문번호 단위 최신 수집본으로 병합한다."""
    if existing is None or existing.empty:
        combined = new_df.copy()
    else:
        combined = pd.concat([existing, new_df], ignore_index=True)

    combined = combined.fillna("").astype(str)
    if _ORDER_KEY not in combined.columns:
        return combined.drop_duplicates(keep="last").reset_index(drop=True)

    if "collected_at" not in combined.columns:
        combined["collected_at"] = ""

    # 아래 블록이 문제: 재수집본에 없는 주문번호는 자기 자신이 max라 생존한다
    order_latest = (
        combined[[_ORDER_KEY, "collected_at"]]
        .groupby(_ORDER_KEY, dropna=False)["collected_at"].max().to_dict()
    )
    order_ids = combined[_ORDER_KEY].fillna("").astype(str).str.strip()
    latest_collected = order_ids.map(lambda oid: order_latest.get(oid, ""))
    keep_latest = order_ids.eq("") | combined["collected_at"].fillna("").astype(str).eq(latest_collected)
    out = combined[keep_latest].copy()

    dedup_cols = [col for col in _ORDER_LINE_KEY if col in out.columns]
    if dedup_cols:
        out = out.drop_duplicates(subset=dedup_cols, keep="last")
    else:
        out = out.drop_duplicates(keep="last")

    return out.reset_index(drop=True)
```

def _resolve_baemin_target_dates(
    stores: list[str],

    """교정 대상 날짜 결정.

    if lookback_days is not None:
        kst_now = pendulum.now("Asia/Seoul")
        return [
            (kst_now - timedelta(days=i)).strftime("%Y-%m-%d")
            for i in range(1, lookback_days + 1)
        ]

    dates: set[str] = set()
    for store in stores:
        dates.update(_collect_baemin_source_dates(store))
    dates.update(_collect_existing_unified_baemin_manual_dates(stores))
    dates.update(_collect_existing_baemin_duplicate_dates(stores))
    return sorted(d for d in dates if re.fullmatch(r"\d{4}-\d{2}-\d{2}", d) and d != today)

## Constraints

- **원천 parquet 스키마 변경 금지.** 배민은 `DB_Beamin_04_orders._COLUMNS` 27개 고정, 쿠팡 orders도 컬럼 추가 금지. 소급 신호는 반드시 `LOCAL_DB`의 별도 JSON 마커로 처리한다.
- 폴더 구조·파일명 변경 금지.
- `dags/db/DB_UnifiedSales_Dags.py`, `dags/db/DB_CollectionCompare_Dags.py`는 수정하지 않는다. `LOOKBACK_DAYS = 14`도 그대로 둔다 (마커가 소급을 담당).
- `shrunk_dates`가 있어도 교체를 중단하지 않는다. `logger.warning`만 남긴다.
- **적재 계약: "그 날짜는 마지막에 올린 파일이 정답"이다.** 주문번호 일치 여부로 교체를 판단하지
  않는다. 1차 수집의 `주문번호 X=100원`과 재수집의 `주문번호 Y=10000원`이 다른 번호여도
  X는 제거되어야 한다(현행 버그의 핵심). 이 계약은 배달완료 0건 파일에도 동일하게 적용된다.
- reconcile 단계에서 마커를 지우지 말 것. 반드시 enforce 단계에서 지운다 (이유: 두 함수가 같은 `_resolve_*_target_dates`를 호출).
- `sale_date` 지정(정정 모드) 실행의 단일 날짜 동작은 바꾸지 않는다.
- 운영 OneDrive 파티션(`BAEMIN_ORDERS_DB`, `COUPANG_ORDERS_DB`)을 테스트 중 직접 수정하지 않는다. 스크래치 복사본 사용.
- 이미 들어간 유령 행은 코드 수정만으로 사라지지 않는다. 해당 매장/월을 **재수집**해야 새 로직이 정리한다. 별도 repair 스크립트는 만들지 않는다 (유령 판정에 원천이 필요).
- print 금지, 절대 import 경로 사용, 하드코딩 경로/스케줄 금지.
