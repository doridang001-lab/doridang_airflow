# Flow 방문일지 데이터마트 (v1: 동탄영천점 / 용인동천점)

## Task

이미 수집된 Flow 원천(`ANALYTICS_DB / "flow"`의 `flow_post`, `flow_comment`, `flow_project`)에서 **방문일지 게시글만** 골라, 방문일자·이슈·점주의견·본사답변으로 정규화한 데이터마트를 만든다. 신규 담당자가 과거 게시글을 하나씩 열지 않고도 매장 히스토리와 대응 방향을 파악할 수 있게 하는 것이 목적이며, 산출물은 **LLM 학습(RAG)용 JSONL + 대시보드용 parquet 마트**다.

v1은 2개 프로젝트만 대상으로 한다: 동탄영천점 `2466857`(방문일지 7건), 용인동천점 `2742104`(방문일지 3건). 총 10건.

**이번 범위 제외(확정)**: 매출 KPI(월매출·순수익·배달비중·객단가·일평균), 광고/플랫폼 요약 → 매출 마트 소관. 대시보드 렌더링도 제외 — parquet + JSONL까지만.

### 반드시 알아야 할 사실

| 항목 | 내용 |
|---|---|
| **`post_date`는 작성일** | `26.03.18 (수) 동탄영천점 방문일지` → `post_date=2026-03-19`. **방문일자로 쓰면 안 된다.** 제목/본문에서 파싱해야 함 |
| **방문일지 식별 조건** | `title.replace(" ","").contains("방문일지")` **OR** `content_text.contains("방문일자")` → 정확히 10건. 제목만 쓰면 `26.03.18 (수) 용인동천점 오픈 2개월 이후 장급 방문`(실제 방문일지 양식)을 놓친다 |
| **본문 양식 2종 혼재** | ① 구형 표-눌림형(7건): `방문일자…방문목적…주제1<제목>전달내용<…>가맹점의견<…>주제2…` ② 신형 자유서술(3건, 김덕기 SV 작성): `1. 매장현황 / 2. 계육 / 4. 담당자 의견 / 5. 점주님 요청사항` |
| **룰 파서 단독 불가** | ①만 파싱된다. ②는 `주제` 토큰이 0개 → **LLM이 주 추출기, 룰 파서는 힌트로만** |
| **댓글 필터** | `is_system=True`는 상태변경 로그(`sys_code="S45^^0^^1"`, 내용 `'요청' → '진행', 상태를 변경하였습니다.`)라 반드시 제외. 본문 빈 댓글(`sys_code="S13"`, 첨부만)도 제외 |
| **파티션 읽기 주의** | `_write_project_partitions()`가 저장 시 `project_id` 컬럼을 **drop**한다. `flow_post/project_id=2742104` 디렉터리를 직접 읽으면 `project_id` 컬럼이 없다. **base dir(`FLOW_POST_PARQUET`)를 통째로 `pd.read_parquet`** 해야 pyarrow가 `project_id`를 파티션 컬럼으로 복원한다 |
| **재실행 캐시** | `flow_post.content_hash`가 이미 있으므로 LLM 캐시 키로 사용 |
| **Ollama 가용 모델** | `qwen2.5:14b`(32k ctx), `gpt-oss:20b`(131k ctx). `get_ollama_client_with_candidates()`가 substring 매칭으로 둘 다 잡는다 |

1. `pd.read_parquet(FLOW_POST_PARQUET)` — **base dir 통째로** 읽어 `project_id` 파티션 컬럼 복원. `FLOW_COMMENT_PARQUET`도 동일.
2. `TARGET_PROJECT_IDS`로 필터(문자열 비교, `astype(str)`).
3. 방문일지 선별:
   ```python
   title_norm = post["title"].fillna("").str.replace(" ", "", regex=False)
   body = post["content_text"].fillna("")
   is_visit = title_norm.str.contains("방문일지") | body.str.contains("방문일자")
   ```
4. 결과를 `{"posts": [...], "comments": [...]}` dict(레코드 리스트)로 반환. XCom 직렬화 가능해야 하므로 `df.to_dict("records")` 사용, `NaN` → `None` 정규화.
5. 0건이면 `RuntimeError`.

#### 4-2. `parse_visit_meta(payload, **context) -> dict`

**본문 정제 `_clean_content(text)`**
- `\xa0`, `​` → 공백
- `https://docs.google.com/\S+` 제거
- `[=~_\-]{4,}` (구분선) → 개행
- 빈 템플릿 잔재 제거: `주제\s*[1-9]\s*(전달내용|내용)\s*(가맹점의견)?\s*(?=주제|\Z)`
- 연속 공백 3개↑ → 1개, 연속 개행 3개↑ → 2개, strip

**방문일자 파싱 `_parse_visit_date(title, content, post_date)`**

우선순위: 제목 → 본문 `방문일자` 직후 25자 → `post_date` 폴백. 반환은 `(iso_date, source)`이며 source는 `title` / `title_md` / `body` / `post_date`.

패턴을 아래 순서로 시도. 2자리 연도는 `+2000`. `datetime.date()` 생성 실패 시 다음 패턴으로.

```python
_DATE_PATTERNS = [
    r"(20\d{2})\s*년\s*(\d{1,2})\s*월\s*(\d{1,2})\s*일",   # 2025년 4월 16일
    r"(\d{2})\s*년\s*(\d{1,2})\s*월\s*(\d{1,2})\s*일",     # 26년 6월 01일
    r"\b(\d{2})\.\s*(\d{1,2})\.\s*(\d{1,2})",              # 26.03.18 / 26.06. 23 (공백 허용)
    r"\b(20\d{2})[-.](\d{1,2})[-.](\d{1,2})",              # 2026-03-18
]
_MD_PATTERN = r"(?<![\d.])(\d{1,2})\s*[/월]\s*(\d{1,2})\s*일?"   # 5/30, 3월 19일 → 연도는 post_date에서 보충
```

본문 파싱은 `re.search(r"방문일자\s*[:：]?\s*(.{0,25})", content)`로 잘라낸 뒤 같은 패턴을 적용한다.

**방문목적 / 주제표 룰 파싱 `_parse_topic_table(content)`** (구형 양식에서만 성공, 실패 시 `None`)
- 목적: `re.search(r"방문목적\s*(.*?)(?=주제\s*1|\Z)", tail, re.S)`
- 블록: `re.finditer(r"주제\s*([1-8])(.*?)(?=주제\s*[1-8]|\Z)", tail, re.S)`
  - **주의**: `주제4` + `9월 사입 결과` → `주제49`로 붙는 케이스가 있으므로 숫자는 반드시 **1자리(`[1-8]`)만** 캡처
- 각 블록 분해: `^(.*?)(?:전달내용|내용)(.*?)(?:가맹점의견|점주의견)(.*)$` (`re.S`)
- 전달내용·가맹점의견이 **둘 다 공백**인 블록은 버린다

각 post에 `visit_date`, `visit_date_source`, `visit_purpose`, `content_clean`, `topic_table`(list 또는 None)을 붙여 반환.

**사후 검증 (LLM 출력을 그대로 믿지 않는다)**
- `issue_key`가 enum에 없으면 → `issue_label` + `owner_voice`를 taxonomy `aliases`와 문자열 매칭해 1회 보정 → 실패 시 `"기타"`
- `issue_key`가 확정되면 `category`는 **taxonomy의 category로 덮어쓴다**(LLM 값보다 우선). `기타`일 때만 LLM category를 쓰되 `VALID_CATEGORIES` 이탈 시 `"가맹점의견"`

- `issues`가 0건인데 `len(content_clean) >= 500`이면 `logger.warning` 후 **1회 재시도**

### modules/transform/pipelines/strategy/SMP_flow_store_collect.py (write helper — 그대로 import)
```python
def _write_parquet_atomic(df: pd.DataFrame, path: Path) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_suffix(path.suffix + ".tmp")
    try:
        df.to_parquet(tmp, index=False, engine="pyarrow")
        os.replace(tmp, path)
    finally:
        if tmp.exists():
            tmp.unlink(missing_ok=True)


def _write_project_partitions(
    df: pd.DataFrame, base_path: Path, columns: List[str], project_ids: Iterable[Any],
) -> None:
    base_path.mkdir(parents=True, exist_ok=True)
    if "project_id" not in df.columns:
        raise RuntimeError("Flow parquet 파티션 저장에는 project_id 컬럼이 필요합니다.")
    normalized = df.reindex(columns=columns).copy()
    normalized["project_id"] = normalized["project_id"].astype(str)
    for raw_project_id in sorted({_as_text(p) for p in project_ids if _as_text(p)}):
        partition_name = f"project_id={_safe_project_partition(raw_project_id)}"
        partition_dir = base_path / partition_name
        tmp_dir = base_path / f".tmp_{partition_name}_{os.getpid()}_{time.time_ns()}"
        group = normalized[normalized["project_id"].eq(raw_project_id)]
        try:
            if partition_dir.exists():
                shutil.rmtree(partition_dir)
            if group.empty:
                continue
            tmp_dir.mkdir(parents=True, exist_ok=False)
            group.drop(columns=["project_id"]).to_parquet(   # ← project_id는 파티션 키라 drop됨
                tmp_dir / "part.parquet", index=False, engine="pyarrow",
            )
            os.replace(tmp_dir, partition_dir)
        finally:
            if tmp_dir.exists():
                shutil.rmtree(tmp_dir, ignore_errors=True)
```
※ `_write_project_partitions`가 `project_id`를 drop하므로, **읽을 때는 반드시 base dir 전체**를 `pd.read_parquet()`해야 `project_id`가 파티션 컬럼으로 복원된다.

## Verification Loop

구현 완료 후 아래 루프를 **모든 Test Cases PASS까지** 반복한다.

```
LOOP until all PASS:
  1. Test Cases 1~14 순서대로 실행
  2. FAIL 항목 → 원인 분석
     - 2번 FAIL → _DATE_PATTERNS 순서/정규식 확인 (2자리 연도, 공백 허용 여부)
     - 3번에서 주제 번호가 2자리 → 정규식을 [1-8] 1자리로 제한
     - 5·6번 evidence_ok=False → 프롬프트의 "원문 그대로 인용" 지시 강화 + 공백 정규화 비교인지 확인
     - 8번 반복이슈 미검출 → taxonomy aliases 보강 또는 프롬프트에 alias 노출 확인
     - 10번 시스템 로그 혼입 → is_system 필터 누락
  3. 코드 수정
  4. 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

## Constraints

- **`post_date`를 `visit_date`로 쓰지 말 것.** 이 마트의 존재 이유가 방문일자 기준 정렬이다
- **파티션 parquet은 base dir 통째로 읽을 것.** 하위 `project_id=xxx` 디렉터리를 직접 읽으면 `project_id` 컬럼이 없다
- **룰 파서만으로 이슈를 만들지 말 것.** 최근 방문일지 3건은 표 양식이 아니라 0건이 나온다. LLM 출력이 정본, 룰 파서 결과는 프롬프트 힌트일 뿐
- **`is_system=True` 댓글은 반드시 제외** (상태변경 로그)
- **`issue_key`의 `category`는 taxonomy 값으로 덮어쓸 것.** LLM이 붙인 category를 신뢰하면 반복이슈/카테고리 집계가 흔들린다
- **LLM 클라이언트를 게시글마다 새로 만들지 말 것.** 한 번 생성해 `client`/`model_candidates`를 계속 넘긴다
- **`evidence_ok=False`인 행을 삭제하지 말 것.** 플래그만 남기고 소비 측에서 거르게 한다
- `json.dumps`는 항상 `ensure_ascii=False`
- parquet/JSONL 저장은 임시파일 → `os.replace` 원자적 교체 (기존 helper 사용)
- 매출 KPI(월매출·순수익·배달비중·객단가·일평균)와 광고/플랫폼 요약은 **이번 범위 아님**. 컬럼도 만들지 않는다
- `TARGET_PROJECT_IDS` 기본값은 `"2466857,2742104"`. 빈 문자열이면 `flow_project.is_store == True` 전량으로 동작해야 한다 (전 매장 확장 대비)
- 기존 `ANALYTICS_DB / "flow"` 원천 데이터는 **읽기 전용**. 절대 수정·삭제하지 않는다
- 방문일지 마트 기본 산출 위치는 `MART_DB / "Flow_mart" / "Flow_visit"`이며, 운영 환경에서만 `FLOW_VISIT_BASE_DIR` env로 덮어쓸 수 있다

## Do Not Ask — Decide Yourself

- 파일이 이미 존재하면: 덮어쓰기
- import가 모호하면: Reference Code의 패턴 따라가기
- 타입 힌트 여부: 기존 파일과 동일하게 (`from __future__ import annotations` + 함수 시그니처에 힌트)
- 주석 여부: 최소화 (WHY만, WHAT 설명 금지)
- 변수명·함수명 스타일: snake_case, private helper는 `_` prefix
- `export_llm_corpus`를 별도 task로 뺄지 여부: 별도 task로 분리
- taxonomy에 키를 더 넣고 싶으면: 넣어도 되지만 기존 키는 **이름을 바꾸지 말 것**
