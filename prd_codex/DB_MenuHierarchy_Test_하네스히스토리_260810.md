## 히스토리

1. 초기 문제는 source별 주문서 옵션 구조가 달라 메뉴별 닭사용량과 메뉴별 수익을 안정적으로 계산할 수 없다는 점이었다.
2. 테스트 매장은 `송파삼전점`으로 고정했다.
3. 산출물 CSV가 너무 많아 운영이 어려웠으므로 루트 산출물은 4개로 줄였다.
   - `01_수기입력.xlsx`
   - `02_최종주문.csv`
   - `03_요약.xlsx`
   - `04_사용법.md`
4. 신뢰도 표기보다 완전분류가 목표이므로 최종 CSV에는 `판정상태`를 노출하지 않고 `분류룰`만 남긴다.
5. 옵션 누락/충돌은 원천 주문에 0원 옵션행을 추가하지 않고 `판정옵션` 시트로 확정한다.
6. 반반 메뉴는 `뼈+뼈`, `뼈+순살`, `순살+순살` 세 조합이 있으므로 2026-08-10에 별도 분해 컬럼을 추가했다.

## 현재 핵심 설계

원천 주문행은 절대 쪼개지 않는다.

이유:

- `_pk` unique 검증이 깨진다.
- source별 매출 검증이 흔들린다.
- 옵션행을 임의 추가하면 원천 주문과 후속 분석의 대응이 어려워진다.

대신 주문 main 행에 닭 사용량 분석 컬럼을 붙인다.

주요 컬럼:

- `닭유형`
- `사이즈`
- `사용용량`
- `사용용량_합계`
- `뼈사용용량`
- `순살사용용량`
- `뼈사용용량_합계`
- `순살사용용량_합계`
- `반반조합`
- `분류룰`

## 닭사용량 계산

`사용용량`은 메뉴 1개 기준값이다.

```text
사용용량_합계 = qty * 사용용량
```

반반 분해 컬럼은 재고와 닭 수량 검증용이다.

```text
사용용량_합계 = 뼈사용용량_합계 + 순살사용용량_합계
```

예시:

| 조합 | 닭유형 | 뼈비율 | 계산 |
|---|---|---:|---|
| 뼈+뼈 | 뼈닭 | 1.0 | 뼈 기준 사용량 100% |
| 뼈+순살 | 혼합 | 0.5 | 뼈 기준 50% + 순살 기준 50% |
| 순살+순살 | 순살 | 0.0 | 순살 기준 사용량 100% |

`뼈+순살` 대 사이즈 예시:

```text
뼈 대 = 1.5
순살 대 = 1.2
사용용량 = 1.5 * 0.5 + 1.2 * 0.5 = 1.35
qty=2이면 사용용량_합계 = 2.7
```

## 반반 처리 규칙

반반 조합은 메뉴/주문 컨텍스트에 `반반`이 있을 때만 자동 확정한다.

이 제한이 필요한 이유:

- 일반 순살 메뉴에 `뼈` 옵션이 붙는 정상 변경 케이스가 있다.
- 이 케이스를 `뼈+순살` 반반으로 오인하면 기존 분류가 깨진다.

자동 확정 기준:

- 옵션 신호가 `뼈`, `뼈`이면 `반반조합=뼈+뼈`
- 옵션 신호가 `뼈`, `순살`이면 `반반조합=뼈+순살`
- 옵션 신호가 `순살`, `순살`이면 `반반조합=순살+순살`

수기 확정 기준:

- `01_수기입력.xlsx > 판정옵션`에서 `반반조합` 또는 `뼈비율`을 입력한다.
- `반반조합=뼈+순살`이면 `뼈비율=0.5`로 해석한다.
- `사용용량`이 비어 있으면 사이즈와 비율로 자동 계산한다.

## 검증 기준

필수 통과 조건:

- `02_최종주문.csv` 행 수와 `_pk` unique가 같다.
- source별 매출 합계가 변하지 않는다.
- `03_요약.xlsx > source별_분류검증`에서 `미분류행=0`이다.
- `03_요약.xlsx > 미분류_TOP`이 0행이다.
- `사용용량_합계 = qty * 사용용량` 오류가 0건이다.
- `사용용량_합계 = 뼈사용용량_합계 + 순살사용용량_합계` 오류가 0건이다.
- option/side 행에는 닭 사용량 분석값이 남지 않는다.

표준 검증 명령:

```powershell
python -X utf8 -m py_compile modules\transform\pipelines\db\DB_MenuHierarchy_Test.py dags\db\DB_MenuHierarchy_Test_Dags.py
python -X utf8 -m pytest tests\test_menu_hierarchy_no_model_classification.py --basetemp C:\airflow\.tmp\pytest -q
```

## 운영 주의사항

- OneDrive 산출물 재생성은 사용자 승인 후에만 한다.
- 루트 임시 파일은 만들지 않는다. 필요하면 `.tmp/`를 쓴다.
- 한글 컬럼 검증은 PowerShell 문자열 리터럴보다 `python -X utf8` 내부에서 처리한다.
- 반반은 확정 분류이고, 기존 `비율추정` 혼합과 다르다.
- 기존 `혼합 + 비율추정`은 신호 없는 주문을 실측 뼈순살 비율로 보정하는 용도다.
