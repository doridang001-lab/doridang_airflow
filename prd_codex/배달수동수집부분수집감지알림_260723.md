### 2. `DB_UnifiedSales_common.py` — 마커 기록 공통화

`record_manual_fallback_marker()`(현 96행)와 `record_manual_item_detail_gap_marker()`(현 157행)가 root만 다른 동일 코드다. 아래로 공통화하고 기존 두 함수는 얇은 래퍼로 남긴다(**호출부 시그니처 유지 필수**).

```python
def _record_marker(root, source: str, store: str, date: str, meta: dict) -> bool:
    """마커를 기록하고 신규 생성 여부를 반환한다."""
    try:
        path = root / str(source).strip() / str(store).strip() / f"{date}.json"
        is_new = not path.exists()
        path.parent.mkdir(parents=True, exist_ok=True)
        payload = dict(meta or {})
        payload.update({
            "source": str(source).strip(),
            "store": str(store).strip(),
            "date": str(date).strip(),
            "updated_at": pendulum.now("Asia/Seoul").isoformat(),
        })
        path.write_text(json.dumps(payload, ensure_ascii=False, indent=2), encoding="utf-8")
        return is_new
    except Exception as exc:
        logger.warning("마커 기록 실패: root=%s source=%s store=%s date=%s | %s", root, source, store, date, exc)
        return False


def _clear_marker(root, source: str, store: str, date: str) -> bool:
    try:
        path = root / str(source).strip() / str(store).strip() / f"{date}.json"
        if not path.exists():
            return False
        path.unlink()
        return True
    except Exception as exc:
        logger.warning("마커 삭제 실패: root=%s source=%s store=%s date=%s | %s", root, source, store, date, exc)
        return False
```

`record_manual_fallback_marker` / `clear_manual_fallback_marker` / `record_manual_item_detail_gap_marker`는 각 root를 넘기는 래퍼로 교체.

### 3. `DB_UnifiedSales_common.py` — 부분수집 감지 함수

기존 `pos_delivery_summary()`(현 57행)를 **그대로 재사용**한다. reconcile 시점(`t_baemin`/`t_coupang`)에는 `build_posfeed`가 적재한 배달 POS 행이 아직 unified 일별 parquet에 살아 있다. ToOrder(검증 기준)를 적재 단계로 끌어들이지 않으므로 순환 참조가 없다.

```python
def detect_manual_partial_collection(
    date: str,
    store: str,
    platforms: set[str],
    manual_source: str,
    manual_total: int,
) -> dict | None:
    """수동수집 합계가 같은 날 POS 배달 합계 대비 과소하면 부분수집 이벤트를 반환한다.

    반드시 _upsert_daily() 호출 **전에** 부른다. 호출 후에는 POS 행이 삭제되어
    비교 기준이 사라진다.
    """
    pos_total, pos_order_cnt, rows = pos_delivery_summary(date, store, platforms, manual_source)
    if rows <= 0 or pos_total <= 0:
        return None

    manual_total = int(manual_total or 0)
    gap = pos_total - manual_total
    if manual_total >= MANUAL_PARTIAL_MIN_RATIO * pos_total:
        return None
    if gap < MANUAL_PARTIAL_MIN_GAP:
        return None

    return {
        "date": date,
        "store": store,
        "platform": sorted(platforms)[0] if platforms else "",
        "manual_total": manual_total,
        "pos_total": int(pos_total),
        "gap": int(gap),
        "ratio": round(manual_total / pos_total, 3) if pos_total else 0.0,
        "order_cnt": int(pos_order_cnt),
    }


def record_manual_partial_marker(source: str, store: str, date: str, meta: dict) -> bool:
    return _record_marker(MANUAL_PARTIAL_MARKER_ROOT, source, store, date, meta)


def clear_manual_partial_marker(source: str, store: str, date: str) -> bool:
    return _clear_marker(MANUAL_PARTIAL_MARKER_ROOT, source, store, date)
```

`platform` 값은 알림 표기용이다. 배민은 `"배달의민족"`, 쿠팡은 `"쿠팡이츠"`를 호출부에서 넘겨도 되므로, 호출부에서 대표 플랫폼명을 이벤트에 덮어써도 무방하다.

```python
    "배민수동": {"배달의민족", "배민1", "배민 포장", "배민 사장"},
    "쿠팡수동": {"쿠팡이츠", "쿠팡 포장"},

def pos_delivery_summary(date, store, platforms, manual_source) -> tuple[int, int, int]:
    """수동 결측 시 유지될 비수동 배달행의 금액/주문수/행수를 반환한다."""
    path = _unified_daily_path(date)
    if not path.exists():
        return 0, 0, 0
    df = pd.read_parquet(path, columns=["store", "platform", "source", "total_price", "order_cnt"])
    store_s = df["store"].fillna("").astype(str).str.strip()
    platform_s = df["platform"].fillna("").astype(str).str.strip()
    source_s = df["source"].fillna("").astype(str).str.strip()
    mask = store_s.eq(str(store).strip()) & platform_s.isin(platforms) & ~source_s.eq(str(manual_source).strip())
    if not mask.any():
        return 0, 0, 0
    total_price = pd.to_numeric(df.loc[mask, "total_price"], errors="coerce").fillna(0).sum()
    order_cnt = pd.to_numeric(df.loc[mask, "order_cnt"], errors="coerce").fillna(0).sum()
    return int(total_price), int(order_cnt), int(mask.sum())
```

## Verification Loop

구현 완료 후 아래 루프를 **모든 Test Cases PASS까지** 반복한다.

```
LOOP until all PASS:
  1. Test Cases 순서대로 실행
  2. FAIL 항목 → 원인 분석
  3. 코드 수정
  4. 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

## Constraints

- **적재 동작을 바꾸지 말 것.** `_upsert_daily()`의 `remove_mask` 로직, `filter_manual_delivery_sources_for_test_stores()`, `enforce_baemin_manual_only_for_test_stores()`, `enforce_coupang_manual_only_for_test_stores()`는 전부 무변경. 부분수집 날도 데이터는 수동 기준을 유지한다.
- `detect_manual_partial_collection()`은 반드시 `_upsert_daily()` **호출 전**에 부른다. 호출 후에는 POS 배달 행이 삭제되어 비교 기준이 사라진다.
- `record_manual_fallback_marker` / `clear_manual_fallback_marker` / `record_manual_item_detail_gap_marker`의 **외부 시그니처를 바꾸지 말 것** (baemin·coupang 양쪽에서 호출 중).
- 알림은 마커로 중복을 억제한다. 매 lookback 실행마다 같은 날짜를 다시 알리면 안 된다.
- ToOrder parquet(`toorder_daily_store_platform`)을 적재 단계에서 참조하지 말 것 — 검증 기준을 적재에 끌어들이는 순환 참조가 된다.
- print 금지, logger 사용.

## 범위 밖 (건드리지 말 것)

- **경북상주점 먹깨비 posfeed 과다**: 6월 unified 2,590,000 vs ToOrder 1,379,000, 7월 1,652,900 vs 590,100. 6월 배민수동은 ±15원으로 정확했으므로 수동수집 문제가 아니라 posfeed 플랫폼 분류 이슈. 같은 매장 `홀 포장`이 unified에서 platform `기타`로 들어오는 것도 별건.
- **광명철산점 07-01~08 ToOrder 기준값 0**: 검증 기준 결측이 20.2% 경보를 만들었다. `_alert_summary_rows()`에서 `excel_total == 0` 구간 처리는 이번 범위 아님.
