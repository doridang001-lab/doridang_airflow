# 주문 교차분석 수정·검증 결과

- 작성일: 2026-09-09
- 처리 버전: `order-cross-v2.4` (주문서 기준 보정)
- 상태: 주문서 기준으로 수정 후 515일 재검증·운영 재반영 완료, 정기 갱신 재활성화. 아래 최초 결과는 v2.3의 이력이다.

## 주문서 기준 보정

- v2.3에서 상품 마스터상 메인인 품목 또는 신뢰 가능한 메인명만 인정하여, 실제 주문서에 메뉴명이 있어도 주문을 제외했다. 이를 검수 필요로 안내한 것은 잘못된 진단이었다.
- v2.4는 주문서 `menu_name`과 실제 품목명을 대조하여 기준 메뉴를 잡고 원본 상품번호를 유지한다. 주문서 메뉴명만 있고 대응 품목 행이 없으면 기존 `MENU::` 번호를 사용한다. 상품 분류·표준명 매핑은 품목 표시와 표준 집계에 활용한다.
- 기준 메뉴 역할은 주문마다 판단한다. 음료 등 비메인 분류라도 주문서 기준 메뉴이면 포함하며, 상품 분류 누락을 주문 제외 사유로 삼지 않는다. 같은 주문의 여러 기준 메뉴와 추가 품목을 교차하며 소속 옵션으로만 제한하지 않는다.
- 2026-09-08 최신 원본의 대상 주문 1,456건 중 1,451건을 분석했다. 남은 5건은 주문서 기준 메뉴가 배달비이거나 리뷰 증정품뿐인 사례다. 상품 분류 미확정과 구분하여 보고서에 표시한다.
- 컬럼명·순서·자료형 18개 유지. 주문서 기준·주문별 역할·다중 메뉴·원자적 교체·실패 복구 등 관련 시험 80개 통과.
- 전체 515일 원본 독립 집계 대조 통과 후 1,545,550행 운영 반영·재읽기 대조 완료(2026-09-09 13:20 KST). 9/8 결과는 4,948행이며 컨테이너에서도 검증했다. 임시 복구본은 남아 있지 않다.
- 운영 교체 후 구세대 정리 과정에서 OneDrive 디렉터리의 읽기 전용 속성 오류를 확인했다. 전용 경로 내부인지 확인한 뒤 해당 속성을 처리하도록 보완하고 재현 시험을 추가했다. 잔여 빈 구세대 폴더를 정리한 뒤 전체 반영을 성공적으로 다시 수행했다.
- 증거: `.tmp/order_cross_final/summary.json`, `.tmp/order_cross_publish_20260909.json`, `.tmp/order_cross_live_verification_20260909.json`. Airflow `order_cross_publish_enabled=true` 복원 완료.

## 변경 결과

- 기존 `order_cross_YYMMDD.parquet`의 18개 컬럼명·순서·자료형과 원본 상품번호 의미를 유지했다.
- 리뷰 혜택, 리뷰 참여 표시, 미선택을 분리하고 리뷰가 메인으로 승격되는 오류를 제거했다.
- 동일 메인 반복으로 상대 품목 수량·금액이 곱해지는 오류를 제거했다.
- 매핑표에 등록된 매장만 남기는 필터를 제거했다. 미분류 품목·메인 미확정 주문은 별도 품질 기록에 남긴다.
- 표준 메뉴별 주문 수는 원본 주문 단위에서 중복을 제거해 집계한다. 메인만 주문한 경우도 분모에 포함한다.
- 표준 메뉴 교차 집계, 메인 주문 수, 품목 연결표, 품질 기록은 `_support/<YYMMDD>/<생성번호>/`에 분리했다. 기존 parquet에 컬럼을 추가하지 않고 메타데이터로 연결한다.
- 기존 보고서는 표준 메뉴별 동시 주문 건수와 메인 주문 대비 선택률을 사용한다. 입력 변경 또는 보조 자료 미준비 시 갱신 대기를 표시한다.
- 입력/매핑/산출물 해시 검증, 날짜별 잠금, 임시 파일 재읽기, 원자 교체, 실패 시 복구, 중단 재개를 구현했다.
- 정기 실행은 08~23시 매시 10·40분이며 최근 3일 우선, 과거 변경 최대 10일을 처리한다. 승인 전에는 DAG가 명시적으로 건너뛴다.

## 운영 반영 범위와 복구

승인받아 반영한 범위는 기존 OneDrive `data/mart/order_cross_analysis`의 완료된 일별 파일 515개와 해당 날짜의 보조 자료, 그리고 정기 갱신 활성화다. 당일 진행 중 데이터, 통합매출 원본, 상품 마스터와 수기 검수표는 수정하지 않았다.

승인 후 반영 직전에 입력·매핑의 변경 여부를 다시 확인한다. 달라진 날짜는 새 입력으로 로컬 검증을 다시 수행하고 검증된 결과만 반영한다. 날짜별 반영 실패 시 기존 결과를 보존/복구한다. 임시 복구본은 `LOCAL_DB/temp/backups/order_cross/<실행ID>/`에만 두고 정상 검증/복구 후 삭제한다.

2026-09-09 사용자 승인 후 12:32까지 515일·223,231행을 반영했고 실패는 0일이었다. 승인 이후 입력·매핑 변경은 없었다. 운영 반영 기록은 [order_cross_publish_20260909.json](../.tmp/order_cross_publish_20260909.json)에 저장했다.

12:33에 Airflow 변수 `order_cross_publish_enabled=true`를 설정했다. DAG는 활성·일시정지 해제 상태이고, 다음 정기 실행은 한국시간 12:40이다. 스케줄은 08~23시 매시 10분·40분이다. 변수의 코드 기본값은 계속 `false`이며 이번에 승인된 환경에서만 지속 운영값을 켰다.

12:35 최종 확인: 운영 파일 515일·223,231행 및 보조 테이블이 검증 후보와 모두 일치했고 최신 입력·매핑 해시 검사를 통과했다. 보존된 임시 복구본은 0개다. 증거: [order_cross_live_verification_20260909.json](../.tmp/order_cross_live_verification_20260909.json).
