# 쿠팡자동수집실패분해결

## Task

쿠팡이츠 크롬 확장 배치 수집(`runner.js`)이 매일 밤 7~16개 매장을 백필 큐에 남긴다.
8/3~8/5 이슈 로그 5개를 소스와 대조한 결과, 실패의 상당수가 **확장 자신이 만드는 밴 압력**
때문이다 — 계정 하나가 최악의 경우 2초 간격으로 71번 페이지를 새로고침하고, 로그인이
서버에 거절당한 직후 10초 만에 다시 요청한다.

**이 작업의 원칙: 쿠팡에 보내는 요청 수를 줄이거나 유지한다. 절대 늘리지 않는다.**
(사용자 확인: "조회를 많이 누르거나 새로고침을 많이 하면 밴을 먹어")

수정 파일은 **단 하나**다.

## Project Conventions

이 태스크는 Python/Airflow가 아니라 **크롬 확장(MV3) 대시보드 스크립트**다.
`runner.js`는 확장 페이지(`runner.html`)에서 도는 IIFE 스크립트이며 빌드 단계가 없다.

- 언어: 브라우저 ES2020 JS. TypeScript·번들러·npm 의존성 없음
- 파일 전체가 `(() => { 'use strict'; ... })()` 하나로 감싸져 있다. 최상위 `export`/`import` 금지
- 로깅: `log(msg)` / `log(msg, 'err')` / `log(msg, 'ok')` / `log(msg, 'info')` 헬퍼 사용.
  `console.log` 금지 — 대시보드 로그창에 안 뜬다
- **`'err'` 또는 `'warn'` 레벨만 이슈 로그 파일(`coupang_issue_log_*.txt`)에 남는다**
  (`downloadLog()` 필터, `runner.js:1778-1784`). 운영에서 봐야 할 줄은 반드시 `'err'`로
- 기존 헬퍼를 재사용한다 (새로 만들지 말 것):
  - `sleep(ms)` `:94` / `rand(a,b)` `:95` — `(a,b) => Math.floor(Math.random()*(b-a+1))+a`
  - `getUrl(tabId)` `:707` — 실패 시 `''` 반환
  - `waitUrl(tabId, regexMap, ms)` `:710`
  - `injectContent(tabId)` `:817`
  - `waitForLoginResult(tabId, ms)` `:960`
  - `setRow(i, {...})` / `recordCategoryResults(cat, acc, stores, payload, ok, note)`
- 정규식 상수: `RE_LOGIN` `RE_ORDERS` `RE_CMG` `RE_MENU` (`:24-28`)
- 주석은 **WHY만**. WHAT 설명 금지. 기존 파일이 한국어 주석이므로 한국어로
- 세미콜론 사용, 2-space 들여쓰기, 문자열은 작은따옴표 + 템플릿 리터럴

**4-a.** `ensureLoggedIn` 신설 — `waitForWujieApp`(`:829`) **바로 앞**에 삽입

> **기존 로그인 루프(`:1059-1096`)를 절대 추출·리팩터링하지 말 것.**
> 그 루프는 `stopRequested` 시 `processAccount`에서 직접 `return`하는 등 호출부와
> 얽혀 있어, 추출하면 전 계정이 한 번에 죽는다. 여기서는 **중복이 리팩터링보다 안전하다.**

```js
  // 수집 도중 세션이 끊겨 로그인 페이지로 튕긴 경우의 복구.
  // 기존 로그인 루프는 호출부(processAccount)와 얽혀 있어 추출하지 않고 독립 구현한다.
  // 호출부에서 reloginUsed 플래그로 계정당 1회로 제한할 것.
  async function ensureLoggedIn(tabId, acc) {
    if (stopRequested) return { ok: false, stopped: true };
    if (!RE_LOGIN.test(await getUrl(tabId))) return { ok: true };

    log(`[${acc.id}] 세션 소실 감지 — 재로그인 시도`, 'err');
    const savedErrText = lastLoginErrText;   // 계정 단위 판정 오염 방지
    try {
      if (!await waitForLoginReady(tabId)) {
        log(`[${acc.id}] 재로그인 실패 — 로그인 폼 미감지`, 'err');
        return { ok: false };
      }
      if (stopRequested) return { ok: false, stopped: true };
      await sleep(4000);   // Akamai 센서 초기화 시간 (최초 로그인과 동일 조건)
      await injectContent(tabId);
      await sleep(300);
      try {
        await chrome.tabs.sendMessage(tabId, {
          type: 'AUTO_LOGIN', platform: 'coupang',
          id: acc.id, pw: acc.pw, storeName: acc.stores[0] || '', autoClick: true
        });
      } catch (e) {
        log(`[${acc.id}] 재로그인 AUTO_LOGIN 오류: ${e.message}`, 'err');
        return { ok: false };
      }

      // 재로그인 후 착지 URL은 orders가 아닐 수 있다 — 로그인 URL의 redirectUrl에 따라
      // CMG/onboarding으로 간다. 그래서 orders 도달만 ok로 보는 waitForLoginResult 대신
      // '로그인 페이지를 벗어났는가'로 판정한다.
      const deadline = Date.now() + 30000;
      while (Date.now() < deadline) {
        if (stopRequested) return { ok: false, stopped: true };
        if (!RE_LOGIN.test(await getUrl(tabId))) {
          log(`[${acc.id}] 재로그인 성공`, 'ok');
          return { ok: true };
        }
        try {
          const res = await chrome.scripting.executeScript({
            target: { tabId },
            func: () => {
              const s = document.querySelector('span.login-error-text');
              return (s && s.offsetParent !== null && s.textContent.trim().length > 0)
                ? s.textContent.trim() : '';
            }
          });
          const txt = res?.[0]?.result;
          if (txt) {
            // 서버 거절 — 즉시 재시도하지 않는다(밴 방지).
            log(`[${acc.id}] 재로그인 거절 (${txt}) — 중단`, 'err');
            return { ok: false };
          }
        } catch (_) {}
        await sleep(800);
      }
      log(`[${acc.id}] 재로그인 타임아웃`, 'err');
      return { ok: false };
    } finally {
      lastLoginErrText = savedErrText;
    }
  }
```
