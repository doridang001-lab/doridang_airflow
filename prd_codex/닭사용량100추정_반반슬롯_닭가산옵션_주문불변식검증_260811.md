## Task

## 문제 진단 (실측)

### 결함 1 — 반반은 슬롯 2개인데 모델은 닭유형 1개

- `_half_combo_from_type_signals`(L2754)는 한 주문에 뼈/순살 신호가 **2개 이상**일 때만 반반으로 인정한다.
- `갈비찜닭 반반세트`는 OKPOS가 `닭도리탕 [뼈]` **한쪽만** 기록 → 신호 1개 → `반반조합` 공란 → 통째로 뼈닭 1.0마리. (7 main행)
- 신호가 2개라 `뼈+순살`로 잡힌 20행조차 `예외보정` 시트가 `닭유형_manual=순살 / 닭사용량_manual=0.8`로 덮어써 **뼈가 0마리**가 된다.
  - 실측: `예외보정` 287행 `3~4인 | 닭도리탕 [뼈] | 닭한마리 [순살]` → 순살 0.8. 정답은 혼합 **0.9** (= 0.5×1.0 + 0.5×0.8)
- 결정타: `_build_judgement_option_input`(L5043-5046)은 `판정상태 != 확정`인 행만 `판정옵션` 시트에 올린다. 반반 행은 이미 "확정:수기"라 **시트에 나타나지 않아 사람이 고칠 수단이 아예 없다.**

### 2. 슬롯 추론 — `_infer_half_slots` (L2754의 `_half_combo_from_type_signals` 대체)

```python
def _infer_half_slots(menu_context: object, ordered_type_signals: list[str]) -> tuple[str, str]:
    """반반 메뉴의 두 슬롯 닭유형을 각각 확정한다.

    신호가 하나뿐일 때 나머지 슬롯을 복제하면 갈비찜닭 반반세트가
    통째로 뼈닭 1.0마리가 된다. 모르는 슬롯은 빈값으로 남겨 수기 입력을 받는다.
    """
```

판정 순서:
1. `menu_context`에 `"반반"`이 없으면 `("", "")` 반환 → 기존 단일유형 경로 유지.
2. 메뉴명 자체가 단일 유형을 확정하면(예: `2인 순살 반반` → `_infer_chicken_types`가 `["순살"]`) **두 슬롯 모두** 그 값.
3. 아니면 그룹 내 `option_kind == OPTION_KIND_CHICKEN_TYPE` 행을 `item_seq` 순서로 읽어 슬롯1/슬롯2에 배정.
   - `닭도리탕 [뼈]`, `닭한마리 [순살]` → `("뼈닭", "순살")`
4. **신호가 1개뿐이면 `(그 값, "")`** — 복제 금지.
5. 3개 이상이면 앞 2개를 쓰고 `충돌:반반슬롯` 사유를 남긴다.

기존 "신호 2개 이상" 게이트는 제거한다. 조합 문자열은 슬롯에서 파생시킨다:

```python
def _half_combo_from_slots(slot1: str, slot2: str) -> str:
    """("뼈닭","순살") -> "뼈+순살". 하나라도 비면 ""."""
```

호출부는 `_infer_chicken_attrs_from_group`(L3087). 기존 `half_combo, half_ratio = _half_combo_from_type_signals(...)` 라인을 슬롯 기반으로 교체하고, 반환 dict(L3123-3132)에 `"반반슬롯1_auto"`, `"반반슬롯2_auto"`를 추가한다. `_build_order_group_attrs`의 `columns` 리스트(L3148-3155)와 병합부(L5657, L5679, L5752, L5923의 `"반반조합_auto"` 인근)에도 같은 두 키를 추가해야 값이 끝까지 전달된다.

## Verification Loop

구현 완료 후 아래 루프를 **모든 Test Cases PASS까지** 반복한다.

```
LOOP until all PASS:
  1. T0 → T12 순서대로 실행
  2. FAIL 항목 → 원인 분석
  3. 코드 수정
  4. 전체 Test Cases 재실행
종료 조건: 전체 PASS + Constraints 위반 없음
```

T6이 `RuntimeError: 메뉴계층 검증 실패`로 죽으면 **먼저 severity를 조정하지 말고** 어떤 `issue_type`이 block인지 확인한다. 신규 미입력(반반슬롯·닭가산·예외주문)이면 WARN으로 내리고, INV-1/2/6 위반이면 **실제 버그이므로 로직을 고친다.**

## Constraints

- **`사용용량` 컬럼을 건드리지 말 것.** 가산분은 `사용용량_합계`에만 더한다. `사용용량`은 메뉴 자체 1개당 용량이라 `메뉴중량` / `뼈순살비율` 마스터의 의미가 여기 걸려 있다.
- **`total_price`를 음수로 바꾸지 말 것.** `수익률` / `예외보정` / `옵션분류` 시트가 `매출합계`를 키의 일부로 쓰므로 기존 수기 입력이 전부 어긋난다. `매출_보정` 신규 컬럼을 쓴다.
- **`CHICKEN_DECIDING_KINDS`(L668)에 `닭추가`를 넣지 말 것.** 닭옵션키가 폭발해 `판정옵션` / `예외보정` 시트의 기존 수기 키가 깨진다.
- **`뼈+뼈` / `순살+순살` 총계가 변하면 실패.** 슬롯 계산이 기존 비율 계산과 동일한 값을 내야 한다.
- **LLM 사용 금지.** `assert_no_model_classification_dependencies()`(L735)가 `qwen_client`, `call_llm`, `query_qwen_json`, `classify_unmapped`, `llm_product_map`, `DB_FinProduct_Map`, `DB_ItemIdAllocator` 를 AST로 검사한다.
- **신규 미입력 항목은 WARN.** `COMPLETENESS_BLOCKING_DIMENSIONS`(L367)가 아니라 `COMPLETENESS_INPUT_WAIT_DIMENSIONS`(L374)에 넣는다. block으로 넣으면 사람이 시트를 채우기 전까지 DAG가 계속 죽어 아무도 산출물을 못 본다.
- **`_attach_chicken_addon_columns`는 `_apply_judgement_options` 이후에 실행.** L5156이 `CHICKEN_USAGE_TOTAL_COLUMN`을 `qty × usage`로 덮어쓴다.
- **`예외보정` 시트를 손으로 편집하지 말 것.** 코드가 반반 그룹의 `닭유형_manual`을 무시하도록 만들어 자기치유시킨다.
- 산출물 경로는 `_ensure_output_path`(L834) 가드 때문에 `NEW_CLS_DIR` 밖으로 나갈 수 없다.
- 범위는 **닭 사용량만**. `profit_missing` WARN 15,796건과 `profit` / `manual_profit` / `material_price` 완결률 0%는 이번에 건드리지 않는다.
