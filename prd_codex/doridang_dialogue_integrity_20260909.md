# 도리당봇 대화 정확성 개선

리더가 담당자와 업무를 이어 물을 때 같은 조회 범위와 근거로 답하도록 수정했다. 내부 로컬 Qwen2.5 14B를 유지하며, 원천 Flow 데이터와 OneDrive 파일은 변경하지 않는다.

## 해결한 오류

- 조민준의 미완료 업무 기한 경과와 모니터링 기한 경과를 분리했다. 2026-09-08 수집 기록에서 미완료 업무는 2건, 그중 기한 경과는 1건이다. 모니터링 기한 경과 1건은 별도다.
- 차보령의 피드백 업무를 2건으로 집계하고, 질문의 잘못된 1건을 먼저 정정한다. ‘성과추적test [결과]’도 피드백이며 기한 미등록이다.
- 메뉴판 댓글의 실제 작성자인 오나영과 댓글에서 언급한 황유경·차보령을 구분한다. 댓글 ID·작성 시각·원문을 보존한다.
- ‘조민준은?’은 직전의 피드백 조건을 유지한다. ‘조민준 전체 현황’은 조건을 초기화한다.
- ‘기한 없는 것만’은 이전 기한 경과 조건을 교체한다. ‘미완료’가 ‘완료’ 조건으로 인식되던 부분도 수정했다.
- ‘왜?’와 ‘내가 뭘 결정해야 해?’에 전체 현황을 반복하지 않고, 각각 기록·확인 한계와 확인할 질문을 답한다.

## 응답 처리

1. 요청마다 게시글·댓글·프로젝트 표와 판단 날짜를 고정한다. 파일 변경 중 조회는 다시 읽고, 지속적으로 변경 중이면 확인 실패로 처리한다.
2. 서버가 원본 집계값과 상태·기한·작성자로 사실 문장을 만든다. 현황·작성자·원문 질문에서는 모델이 사실 근거만 선택한다. 리더의 결정 요청에서는 근거에 맞는 확인 질문을 생성한다.
3. 초안 구조, 근거 ID, 사실값 우회 삽입을 검사한다. 모델이 생성한 제안은 같은 근거로 별도의 로컬 Qwen 검수를 거친다.
4. 실패하면 한 번만 재작성한다. 재실패 또는 요청 전체 60초 제한에 도달하면 확인된 사실만 표시한다.
5. 검증 전에는 상태 안내만 보내며, 최종 본문만 SSE로 전달하고 로컬 대화 기록에 저장한다. 검수 실패 설명에 포함될 수 있는 초안도 응답 메타데이터에 노출하지 않는다.

클라이언트 문맥 버전은 2다. 기존 SSE 형식과 `delta`·`answer` 이벤트를 유지하며, 최종 이벤트에 검증 결과와 근거 참조를 추가했다. 서버 메모리가 초기화돼도 브라우저의 마지막 완료 문맥으로 이어진다.

## 검증 방법

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_doridang_bot_routing.py tests/test_doridang_bot_dialogue.py tests/test_doridang_bot_integrity.py tests/test_doridang_bot_browser.py -q
.venv/Scripts/python.exe -X utf8 scripts/eval_doridang_integrity.py --output .tmp/doridang_integrity_eval_final.json
```

자동 검사와 실제 모델 평가를 구분한다. 모델 평가는 2026-09-09로 고정한 최소 재현 자료로 6개 대화 흐름을 각각 3회 실행한다. 최소 자료의 건수를 실제 전체 팀 건수로 사용하지 않는다. 운영 전후 HTTP 검증은 전체 저장 자료를 읽어 사용자의 4턴 대화를 재현한다.

검증 결과:

- 기능·근거·스냅샷·시간 제한·브라우저 검사: 150건 통과.
- 실제 Qwen 평가: 39응답에서 검사 대상 오류 0건, 사실 대체 응답 0건. 초안 3건을 차단하고 각 1회 재작성 후 통과했다.
- 고정 표본의 응답 시간: 평균 4.60초, 최대 10.17초.
- 결과 파일: `.tmp/doridang_integrity_eval_final.json`. 숫자와 필터뿐 아니라 후속 질문에 같은 현황을 반복하는지도 검사했다. 최종 응답의 작성자 인용과 결정 제안을 별도로 읽어 확인했다.
- 전체 저장 자료를 사용하는 검증 서버(8789)와 운영 서버(8788)에서 각각 사용자 사례 4턴을 통과했다. 운영 응답은 2.80~5.70초였고, 검증된 최종 본문 외의 `delta` 전송은 없었다. 기록은 `.tmp/doridang_verified_http_8789.json`, `.tmp/doridang_verified_http_8788.json`에 있다.
- 운영 주소의 새 클라이언트 버전 `20260909-verified`를 확인했다. 모델 교체·외부 API 도입·OneDrive 원본 변경 없이 반영했다.

## 한계

같은 모델의 추가 검수는 독립적인 사실 증명이 아니다. 수치·상태·작성자·인용은 서버의 원본 참조로 제한하고, 자유로운 해석은 추가 검수와 재작성·대체 응답으로 방어한다. Flow 등록 상태만으로 현장 완료 여부나 개인의 책임을 단정하지 않는다. 수집 파일 묶음에 공통 배포 번호가 없어 수집 실행 전체의 원자적 게시까지 보장하지는 않으며, 한 요청 안의 재조회 일관성을 보장한다.
